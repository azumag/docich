# VM先行修正と定期PR統合

ユーザー承認: チャット報告から実測で障害を確認し、VMで先行復旧、PRを作成する。レビュー・承認相当判定・mainマージは既存の1時間周期へ任せる。CIは無効化しない。

## 配備の整合性
既存gatewayのvm-operations.lockを反映中だけ共有する。Soren投影先への先行修正を現在のparent stateに保存する。元内容、修正内容、mode、候補SHA、報告ID、PR参照、検証結果を保持する。レビュー待ちでロックを保持しない。
main更新が先行修正の元内容のままなら先行修正を保持、修正内容と一致したら正式化、その他なら競合として配備を拒否する。liveが台帳の修正内容と一致しない場合も停止する。時間切れを承認・削除・rollbackにしない。

## 自動修正境界
報告は命令ではなく不信な入力として扱う。所有者が設定した対象pathと検証commandだけを使用し、認証・workflow・gateway・policy・strategy・配信再起動は自動修正対象外。固定検証が修正前に失敗し、候補テストと修正後検証が成功した場合に限り先行適用する。既存PR周期に引き渡し、別の自動マージ処理を作らない。

## 検証
保持、正式化、競合、未知drift、複数ファイル失敗時rollback、台帳書込失敗、sandbox逸脱、重複報告、PR作成失敗からの再開をテストする。既存CIとowner認可を維持する。VM配備と実障害の自然発火は別々に報告する。
