# バルーンフィンチ：被ダメージに応じたシャウト（2026-10-16）

本書は `hanjuku_script_bot.md` の「HP9999まで必ずふくらむ／9999の時だけシャウト」という2026-10-06の専用戦術を、2026-10-16のオーナー指示に従って更新する。全回復は常時の必須条件ではなく、被ダメージを推定できない場合の従来フォールバックとして残す。

## 選択条件

味方のバルーンフィンチ本人と「ふくらむ」「シャウト」の技メニューを確認した場合だけ適用する。シャウトで自分のHPも半減するため、判定には使用前HPではなく `現在HP // 2` を使う。

```text
D = 現在の戦闘・相手について採用したターン被ダメージ推定の最大値
安全側の1回分 = ceil(D × 1.25)
シャウト可能 = 現在HP // 2 > 安全側の1回分 × 3
```

「数回」は既定3回、変動への余裕は25%とする。等号ではHP0になるため、3回後にもHPが残る厳密な不等号で判定する。例えばD=200なら1回分250、3回分750なので、HP1800では半減後900が残り、9999を待たずシャウトする。必要HPの下限は1502。HP1500や1501では「ふくらむ」に戻る。

被ダメージ推定が未知の間は9999未満で「ふくらむ」、9999で「シャウト」。推定値による目標が9999を超える場合も、上限で回復を繰り返すループを避けるため従来どおりシャウトする。これは3回耐えられると確認した扱いではなく、`hp_cap` として区別する。

## 被ダメージ推定の採用条件

「ふくらむ」の実カーソル位置を確認してA入力を返した時のHPを保存し、次に味方の技メニューで増加したHPを読めた時だけ、`前回HP × 2 - 今回HP` の正の差を採用する。これはゲーム内部の確定ダメージ値ではなく、技選択とメニューHPの変化に基づくターン損失の推定である。敵攻撃が回復より先なら損失を2倍に数えるため、安全側に大きくなる。

- 上限で回復量が切り捨てられる場合は被ダメージを隠す可能性があるため採用しない。
- シャウト後のHP減少は自分の半減が混ざるため、被ダメージの学習に使わない。
- ゼロ差、選択未確認、同じ画面の繰り返し、予測カーソルだけのA入力は新しいダメージの根拠にしない。
- 回復後にHPが増えない／想定を超える等の不整合が見えた場合は、古い小さな推定を捨てる。
- 推定の最大値は同じ戦闘内で下げない。将軍・相手モンスターが変わる場合や、HPが未読の場合は使い回さない。状態は `battle.balloon_finch_survival` に保持し、別戦闘へグローバル保存しない。

この推定と25%の余裕は、未観測の強攻撃・割合攻撃・即死を防ぐ保証ではない。実戦での被弾推移と選択理由を確認して評価する。ゲームの技仕様の参照元は [GCGX カラフルエッグ](https://gcgx.games/hanjuku/colorful_egg.html)（ふくらむ：自分のHP倍増、シャウト：敵味方HP半減）。

## 記録・検証

既存の `monster_menu_choice` に `observed_metric.balloon_survival` を追加する。`incoming_damage`、`buffered_damage`、`survival_hits`、`post_shout_hp`、`target_hp`、`damage_samples` と選択ルールを記録する。一般の経験学習やHPだけの退却判断は、この専用戦術を上書きしない。他の召喚獣の戦術は変更しない。

対象テスト：

```bash
python -m pytest -q tests/test_hanjuku_balloon_survival.py tests/test_hanjuku_balloon_menu.py
python -m pytest -q tests/test_hanjuku_chart_bot.py -k 'balloon or monster'
```

新しい判定の境界、半減の除外、上限での学習禁止、重複観測、相手・戦闘変更、JSON保存復元と、回復→シャウトへのカーソル移動→A確定→再回復を検証する。合成された読取結果のテストは、自然な実戦・実入力成功・勝敗・本番配備の証明とは分けて扱う。
