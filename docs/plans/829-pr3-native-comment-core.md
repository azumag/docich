# #829 PR-3: native comment core — slices

PR-3 of #829 §14 ("native comment core": message DTO, identity, dedup/pending,
viewer memory, prompt, generation, guard, translation, delivery contract;
prove a game-context-free fixture needs no soviet_now checkout) is split into
reviewable slices. Each slice is **inert** (no production caller) until the
shadow / cutover PRs, and each is pinned against the legacy shell by a golden
generated by *executing* soviet_now's code, not by retyping it.

Baseline: soviet_now `a4db396b` (`broadcast/comment.sh` 3843 lines after the
classifier moved out in soviet_now#495). Stage map: `829-pr0-baseline-inventory.md` §1.

## Notes from 3a

- `_group_comments_by_category` is dead code in the legacy file (defined,
  never called) and is not ported.
- The legacy prompt reads mode assets with `$(cat …)`, which drops trailing
  newlines; `mode_assets()` does the same so rendered bytes stay identical.
- The legacy inline python blocks fail as a whole on malformed classifier
  rows (`dominant` → exit 1, formatted classifications → empty); the ports
  return `None` / `""` instead of raising, matching that.
- `comment_response.md` is a radio input (`radio_engine.sh`), not a comment
  template, and belongs to the radio slices (PR-4).
