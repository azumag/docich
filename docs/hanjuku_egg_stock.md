# 観測した卵残数と回復効果を区別する

## 根拠

2026-10-09確認。SFC版の資料を参照する。

- [GCGX: エッグ](https://gcgx.games/hanjuku/egg.html): エンジェリンで残使用回数を5にできる。ただし初期最大1回のエッグは増えない。
- [RRPG: たまご](https://rrpg.jp/hanjuku_hero_2/egg.html): エンジェリン使用時の5回、いっぱつエッグとキングエッグの1回制限を説明している。
- [GCGX: 切り札](https://gcgx.games/hanjuku/kirihuda.html) / [RRPG: 切り札](https://rrpg.jp/hanjuku_hero_2/trump.html): 回復効果の補助照合。

ユーザー提示のatwikiページは攻略リンク集として確認したが、数値仕様の独立した根拠とはしない。livedoorの指定タグページは取得できなかったため、内容を確認済みとは扱わない。

## 実装境界

`hanjuku_egg_stock.observed_uses` は、直接読んだ残数の共通数値検査を担う。厳密な整数0〜5だけを受け取り、それ以外を `None` とする。卵の種類別の効果計算や使用履歴推定を行う関数ではない。

将軍ステータス、帰還後の野営ステータス、出撃画面、防衛用read modelで同じ上限を使う。名前部分へ余分な数字を押し込んで「14」を残数4として読んだり、出撃画面の6以上や複数桁を有効残数としたりしない。未読、別人、別run、古い画面を現在の本人の状態へ昇格する許可は追加しない。

明示的な5回を観測した場合は、その本人の古い0回を更新できる。これにより既存の卵使用可否・回復費用見積もりに正しい値が渡る。支払、エンジェリン使用、召喚成功、移動入力の受理、城への帰還完了を新たに確定するものではない。

月初回復の既存目標（通常4回、一回型1回）は不変。エンジェリンを選択しただけで残数を5へ変更しない。卵なし・破損は残数0と区別し、卵が5回でも低HPの主人公を安全と断定しない。防衛read modelへの接続先を増やしたり、自動並べ替えを解禁したりしない。

## 検証と未確認事項

`tests/test_hanjuku_egg_stock.py` は既存の合成ネイティブ字形・画面レイアウトを通す85ケース。元コードで23失敗・62成功、修正後85成功を確認。野営の本人/匿名/再試行上限経路、古い0の更新、他人・別identityの拒否、月初目標、瀕死警告、残数の型・範囲と桁数を含む。

[隔離検証run](https://github.com/azumag/docich/actions/runs/37822151947) では半熟英雄全テストとretro/corner rotationの隣接テストも3639成功・10skip・87subtest成功。skip対象や本番の実フレームはこの結果だけでは検証済みとしない。実戦勝率、実ゲームでのエンジェリン発動、常駐runへの反映、本番VM現物一致は未確認。

検証用の一時workflowは専用feature branchだけで利用し、PR作成前に削除する。mainへ恒久的なコード自動書換えworkflowを追加しない。最終HEADの通常CIを別途確認してからマージする。
