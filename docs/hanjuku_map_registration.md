# 全話の城候補とラン内の実位置確認（#2361）

第3話以降は静的な `CASTLES` が空なので、既存の出撃手順が記述されていても
`chart_unavailable` になっていた。本変更は公開資料の候補カタログと、ゲーム画面で
確認した地点を同一ランの既存出撃処理へ渡す経路を追加する。
実機での第3話出撃・復旧・全話完走は未検証。資料の点をネイティブ座標として登録した変更ではない。

## 通常城を確定する経路

対象は静的な座標がない話の、ランID・世代・leaseがそろった256×224の観測。
城名はその話の通常城カタログとの完全一致で扱う。

1. 二つ以上の屋根が見える自由カーソル画面を話内の座標原点とする。
   1屋根だけで開始した場合は、資料の最初の目標への方向をヒントに自由カーソルだけを
   各軸最大256フレーム・合計最大32入力で探索する。3観測連続でカーソル・屋根位置が
   動かない場合も停止する。2屋根が現れるまで座標登録・A入力は許可せず、
   送った移動量を後の座標へ引き継がない。
2. 二つ以上の屋根が支持する一意な平行移動でカメラ移動を測る。
   送信した十字キーの時間は異常移動を拒否する上限にだけ使い、座標の積算には使わない。
3. 公開画像の相対差×8は探索ヒントに限る。候補点に屋根がなければAを許可しない。
4. 屋根上に自由カーソルが静止する二観測後、城を開く。
   出撃選択へは進まず「ステータス」の名前を読む。
5. 完全な城ステータスから同じ実城名を異なる連続観測で二度読んだ場合だけ地点を保存する。
   候補との不一致・別章の城名・未読文字・既知地点との矛盾は登録しない。
6. 保存にはランID・話・原点フレーム・地図フレーム・ステータスフレームのRGB SHA-256を付ける。
   `decide()` の呼出し中だけ `ContextVar` で既存の地図参照へ公開し、静的辞書は書き換えない。

初期候補の優先順は本城、既存手順の出発城・目標城、残りの通常城。
出発城と目標城の両方が確定した手順だけが既存の `orders()` に現れる。
出発城のoverrideと将軍追従候補も登録済み地点に制限し、実効出発城を検証する。
`decide()` が渡すランIDが欠落・不正でも検証を省略しない。ラン内地図が無効なら
既存の暫定注文も停止し、出発城・目標城の座標参照直前にも未登録を拒否する。
城メニュー・将軍一覧・携行選択・出撃確認の各継続画面でも観測ごとに両端点を
再検証し、launched未確定の出撃の照合はそのまま続ける。
未送信の注文を出撃済みや失敗へ書き換えず、入力を返さない。
探索が処理を譲るのは `next_order()` が実際に選択できる手順を返す場合に限る。
空の本城・本城喪失・未登録城への将軍移動だけでは未登録地点の探索を止めない。
第3話の本城とグリンが確定すると `3-Z1` が利用可能になる。
将軍・切り札・城の保護・出撃確認は従来の経路が引き続き担当する。
探索だけで出撃済み記録を作らない。

上位処理への割込みや観測欠落で連続性が切れた後は、既知の城名を再確認するまで
新しい地点を追加しない。探索は候補96観測、パネル確認12観測で有界化する。
確認不能時の保留を汎用の無入力タイムアウトがA入力へ変換しない。
全通常城の登録後は既存のチャート外候補選択へ戻る。

月次の全将軍ステータス読取は城・家の座標を必要としないため、第3〜12話でも行える。
家への修復出張は別の校正値が必要であり、未校正の話では引き続き行わない。
全体図の旗、全体図カーソル、家のハート位置は異なる測定量で、独立した校正値のまま扱う。


## 近似シード（`approx_map`）と実測への移行

第3〜12話を「まず動かす」ための近似シードを `hanjuku_chart.CASTLES_APPROX` に置いた。
`config/games/hanjuku-hero.toml` の `[hanjuku].approx_map = true` のときだけ、
`decide()` の呼出し中に限って `castles()` がこの表を返す。既定（テスト・明示OFF）は
従来どおり空で、`chart_unavailable` のゲートを維持する。

- 値は `SOURCE_CASTLES` の公開130×130旗bboxから `x=8*(left+1), y=8*(top+3)` で作る。
  第1・2話の実測値との差は最大x6・y8 pxあり、**ネイティブのカーソルセルではない**。
  城メニュー・屋根位置の既存確認（`_hold_off_castle` / `_align_on_roof` / `_target_roof_under_marker`）は
  そのまま残すが、誤差による取り違えを完全には防げない。
- `CASTLES` の実測値が常に優先する。`approx_map` 中は `map_registration.step` を止め、
  近似セルで通常城の注文を解放する。ボスは含めない。
  - 第9話の `9-B1` など、`ボス` を target にする注文は座標がないため `orders()` から落ちる。
    第3話の `ボス` は実測済み。第4話は4地点のセル（下記）を持ち、`4-B1`〜`4-B4` がそれぞれを target にする。
  - 全通常城を取った後はボス注文がなくなるため、ボス攻略には実測（下記）が必要。
- `CASTLES_APPROX` はデータであり、`CASTLES` / `WORLD_MAP_OFFSET` / `Y_JUMP_OFFSET` /
  `HOUSE_VIEW` を書き換えない。近似を止めれば従来の `chart_unavailable` に戻る。
- 近似セルで屋根に再アンカーできない観測が4回続いた場合は、そのラン・章で
  `approx_fallback` を立てて近似を隠し、`map_registration` の実測探索へ戻す。
  近似の誤差で注文が動かない場合の有界な退避であり、実測が成立すればその章の
  出撃は再開する。`approx_map` の設定自体は変更しない。
  この退避は近似表で動いている章（`CASTLES_APPROX` にある章、`approx_chapter()`）に限る。
  実測済みの章では `approx_map = true` でも走らない（g1075 2026-10-29 09:14:55〜09:15:56 JST:
  第3話で退避が暫定 order を落とし、同じ order を選び直して `situation_held` を繰り返す
  6 秒周期の停滞が定期 SELECT まで約 1 分続いた）。

### 近似を実測へ置き換える手順（C）

第3話は 2026-10-28 に隔離 libretro プローブ（g1067 の第3話セーブ）で実測済み。
Y で各旗へ飛び、着地した自由カーソルを最寄りの屋根へ合わせ、A の城名で9城すべてを確認した。
`CASTLES[3]`・`WORLD_MAP_OFFSET[3]`・`Y_JUMP_OFFSET[3]` を持ち、近似表と実行時登録は使わない。
ボス城は本番 g1075 の Y 全体マップ（通常城 8 つを全制圧した後のフレーム）から読み取った。最初の登録 (596, 640)（#2949）は破線の輪の中心のアイコン（view (136–138, 127–129)）を城の建物と読んだが、これは崖に囲まれた洞窟だった（GCGX 第3話: 洞窟の周りの黒い所は崖。フィールドでは 3-B1 の出撃先マーカーが毎回氷山の洞窟入口に乗った）。攻略 Wiki の城配置図で ❾完熟プリンス城は最上段の左寄り（アルマムーンと同じ段）にあり、Y ビューのその位置にあるのはドクロ（灰色 view (101–107, 64–69)）だけで、敵将軍のアイコンはそこから散っていく（2026-10-29 14:25–14:29 JST）。その中心 (104, 66.5) を照準にした v293 の (328, 152)（#2993）では、Y 決定後のフィールドでマーカーの中心 (138, 123) がドクロ位置の高層の建物（画面 98–125 × 82–142）の右 6 px 外に落ち、アポロンは建物に触れずにそこで野営した（14:56–14:58 JST）。マーカーから建物中心 (111.5, 112) までの差 (−26.5, −11) px だけ動かし、照準 (101.25, 65.125) の `CASTLES[3]['ボス'] = (306, 141)` にした（v295）。本番は読み取り専用のため A 押下による城名確認はしていない。ボス目標の取消はセルごとに数え、撤回したセルでの取消は新しいセルの再試行を止めない。

第4〜12話の通常城は GCGX の旗座標から入れている。旗の左上はゲーム内の城タイル＋(2, 1)で、
WRAM 0x1700 の城レコード（16バイト、`[id, x, y, …]`、8pxタイル）と第1〜3話の24城すべてで一致した。
セルは `8×(旗＋(1, 3))`（`CASTLES_APPROX` と同じ式）で、実測済みの通常城とは8px以内
（第3話の本城だけ16px）。Y ジャンプで着地し、残りは屋根へ合わせる。ボス城は旗表に無いため未登録。

ローカルのエミュレータで章ごとのネイティブフレームを取得し、`hanjuku_measure` の
入力契約（256×224 RGB、順序付き `(frame, label)`）で城の屋根と実城名を対応させる。
確定したセルを `CASTLES[chapter]` へ入れ、その章を `CASTLES_APPROX` から外す
（`approx_map` は他章のために残してよい）。ボスは章の全通常城制圧後の画面で
`CASTLES[chapter]['ボス']` を実測する。第4話は4地点、第9話は移動ボスなので
単一の `ボス` セルにしない。実測値と近似値が同じ章に混在する間は、実測値を優先する。

## ローカル検証

`test_hanjuku_map_discovery.py` はネイティブ形式の合成画像で登録取引と
`decide()`→`3-Z1` の選択を検証する。地理座標自体は合成値であり実測地図ではない。
本城中心の1屋根から始まり、グリンが画面外となる配置（差144・160px）も検証する。
既存g706城ステータス画像の実城名・話の一致も検証する。
`test_hanjuku_map_registration.py` は資料の件数・城名の一致、既存校正値の保持、
月次ロスター読取と修復出張の独立ゲートを検証する。
実機復旧・VM配布・本番反映・全話完走の証拠にはしない。
