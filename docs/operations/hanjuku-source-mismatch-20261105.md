# 城の取り違えは「同じ城を続けて開いたとき」だけ失敗として数える（v417、2026-11-05）

## 症状（実測）

ボス指示 `A:bf8c3dee:M256898` で、出撃元 オケアナを狙って城メニューを開くと、
実際に開いた城は **アルマムーン**（本城）だった。`source_castle_mismatch` は
3件のみで、いずれも同じ本城。

- 取り違えのたびに `mem['cursor']` を実際の城へ直している（位置推定の修正）。
- しかし `source_miss` は無条件に加算されるため、3回で「出撃元を諦める」判定に達し、
  本城へフォールバックしていた。
- 別の城を開けているなら位置推定は前進しているので、同じ失敗として数えるべきではない。

## 変更

- `deploy._count_source_mismatch(mem, step, label)` を追加。
- **直前に取り違えた城と同じ城**を開いたときだけ加算し、違う城なら 0 から数え直す。
- `SOURCE_MISS_LIMIT`（3）の意味はそのまま（同じ城を3回続けて開いてしまう場合に諦める）。

## 検証

- `tests/test_hanjuku_source_mismatch.py`（新規3件）: 同じ城は加算／違う城は0から／注文ごとに独立。
- 修正前は3件とも失敗、修正後 3 passed。関連（`source_content_key` / `chart_bot` / 層）339 passed。

- 位置推定がずれる根本原因（Yジャンプの確定値や屋根アンカー）は未特定。
- 第6話ボス城への入城は依然として未実測。
