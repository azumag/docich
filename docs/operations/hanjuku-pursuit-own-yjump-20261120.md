# 半熟英雄: ボス追撃は自分のYジャンプでマーカーを置いてから確定する（v1254、2026-11-20）

## 症状（本番 g1288 / v1251 の実測）

第9話のボス追撃が「再照準した」と記録しながら、将軍がまったく動かなかった。

- 13:48〜13:56 の `boss_pursuit_redirected` は4件。直後の入力列は
  `a`（武将メニュー）→ `a`（いどう）→ `a`（目的地確定）で、**Y入力が無い**。
- 全体マップの `world_map_units`（▲＝行軍中の部隊）は 11:35〜13:55 の全観測で
  同じ2隊が同じセル `(118,160)` / `(406,224)` のまま。新しい▲は一度も出ていない。
- 追撃の `target_cell`（青いGマーカーの画面位置）は毎回 `(130〜142, 113〜125)` で
  画面中央付近。視点は将軍にジャンプしたままで、マーカーは将軍自身のタイルを指していた。

## 原因

`boss_pursuit` の目的地判定 `_target_roof_under_marker` は、`y_jumped['PURSUIT']`
の受領印があればマーカーの実位置を見ずに確定する。SELECTで将軍へ視点を飛ばすと
カメラは動くが、`update_world` はマーカーの**画面位置**（中央のまま）から移動量0を
積分するため、直前のYビューで測ったボスセルが `mem['cursor']` に残る。すると
Yジャンプ無しでも「マーカーはボスセル上」と判定され、将軍自身のタイルへの
いどう（＝動かない）を確定していた。前回の受領印が残っていた場合も同じ。

## 変更

- `flows/boss_pursuit.py`: 名簿でSELECTを押す瞬間に、古いカメラ推定
  （`mem['cursor']`）と `y_jumped['PURSUIT']` の受領印・`y_jump_return` を捨て、
  `uncertain=True` にする。追撃の目的地は必ずこの追撃自身のYジャンプで
  置いたマーカーだけを根拠に確定する。
- `version.py`: `hanjuku-chart-v1254-pursuit-own-yjump`。
- `ops/vm_actions/collect_diagnostics.py`: hot-load版の許可リストへ追加。

## 検証

- 追加: `tests/test_hanjuku_boss_pursuit_yjump_required.py`（3件）
  - SELECT時に古いcursor・受領印・y_jump_returnが消え uncertain になる
  - 受領印が無ければdest相はYジャンプを開始し、redirectを記録しない
  - この追撃で得た受領印があれば従来どおりAで確定する
- 既存の追撃テスト・キー台帳・状態領域: 79 passed。

## 未確認・残件

- 実機で「Y→A」の順になり、▲が増えてボスへ行軍するかは未確認。
- 移動ボスへの追いつき（先行・待ち伏せ）は別問題。本変更はまず
  「再照準が実際の行軍になる」ことを成立させるもの。
