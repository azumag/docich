# 半熟英雄: 読めない画面では中央サンプリング再標本化も試す（v645、2026-11-10）

## 症状（実測 22:35）

商店の画面（「なにを かいあたえますか?」）で `parse()` が**文字0件**になり、ボットが保留の
まま止まりました。同じフレームでも**中央サンプリングの最近傍リサンプル**（`x_src = x*299/256 + 0.5`）
だと 20文字以上読めることを実測しました。

## 原因

`Frame.resized()` は HP 数字を守るためのコントラスト保持型フィルタで、一部のパネルでは
グリフ照合が全滅します。一方、単純な中央サンプリングは別のパネルで有効でした。

## 修正（v645 `hanjuku-chart-v645-dual-decode`）

脳（`brains/hanjuku/bot.py`）に `_decode_frame()` を追加しました。

1. まず従来の `resized()` で読み、**40文字以上**読めればそれを使う。
2. 読めない場合だけ中央サンプリングで再標本化し、**より多く読めた方**を採用。

余分なデコードは「読めない画面」だけなので、通常時のコストは増えません。

## 確認

- `tests/test_hanjuku_dual_decode.py`（2件）。
- スクリプト・診断 140件超 passed。
- 実測: 商店フレームで **0文字 → 「14ねん9のつき…しょうぐんぼしゅう…」** に改善。
