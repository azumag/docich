# 地図フレームの間隔が空いても位置を積分する（v432、2026-11-05）

## 症状（実測）

`cursor` が [392,144] のまま数時間動かず、`nav_last` は null、`uncertain` は true。

- `update_world` は「前の地図フレームが**ちょうど1 tick 前**」のときだけ画面の移動量を積分します。
- しかし第6章は戦闘が多く、**地図のフレームが8.4分で2回**しか来ません。
- そのため連続性の条件が常に外れ、位置の積分が起きず、推定が凍結していました。

## 変更

- `os_layer/world.NAV_CONTINUITY_TICKS = 30` を追加し、`gap = tick - last_tick` が
  `0 <= gap <= 30` かつ同じ画面種別なら積分する（従来は `gap == 1` のみ）。
- 長く離れた場合は従来どおり積分しない（戦闘でカメラが動いた可能性があるため）。

## 検証

- `tests/test_hanjuku_nav_continuity.py`（新規2件）: 30 tick 以内の間隔は積分する／
  31 tick 以上は積分しない。
- 関連（`chart_bot` / 層 / `cursor_still` / `map_discovery`）412 passed。
