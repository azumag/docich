# 半熟英雄: 第6話の行軍上限を実測の遅い側に合わせる（v549、2026-11-09）

## 症状

g1163 第6話 2026-11-09 09:42:31 JST。ラビオリの アルマムーン → セレーネ 行軍が
**1701観測**で `sortie_march_overdue`（上限内に入城も経由も観測されない）と判定され、
オーダーが未発射に戻りました。

## 原因

`os_layer/world.MARCH_TICKS_PER_CELL = {6: 2.4}` は、同じコメントにある実測
「603セルで23〜32分、740セルで34分」の**遅い側**をカバーしていませんでした。

- 603セル × 2.4 = 1447観測（上限）< 実測の遅い側 1920観測（32分）
- そのため、まだ到着し得る行軍を途中で「期限超過」と判定し、同じオーダーを
  再送していました（重複行軍・将軍の二重使用の恐れ）。

## 修正（v549 `hanjuku-chart-v549-march-rate`）

`MARCH_TICKS_PER_CELL = {6: 3.2}` へ引き上げます。

- 603セル → 1930観測（32分をカバー）
- 740セル → 2368観測（34分をカバー、上限 `6 * SORTIE_BUSY_TICKS` = 2400 以内）
- 上限を超える場合は従来どおり 2400 で頭打ち。ボス行軍は従来どおり上限を使う。

## 確認

- `tests/test_hanjuku_march_evidence.py` に1件追加: 実測の遅い行軍（603セル・740セル）が
  上限内に収まり、かつ上限2400を超えないこと。
- 行軍・出撃期限・チャート外 125件 passed。
- 本番反映後: `sortie_march_overdue` の件数が減り、同じオーダーの再送が減ることを実測する。
