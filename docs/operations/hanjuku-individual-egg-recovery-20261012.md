# 半熟英雄の低残数卵の個別回復

全回復が払えない月は、実一覧で確認した残数0・1の一般将軍の卵から個別回復する。
残数0を1より優先する。全回復が払える場合と既存の主人公優先経路は維持する。
全回復の実見積が不足した場合も、1個分と賃金・修復費を残せれば一度だけ実一覧へ戻る。

選択は本人行と実カーソルで行い、同run/chapter/monthの所有する取引で1個50Gの
実見積を確認する。完全・最新・同identityの所属と全員の賃金が読めた場合だけ実額を
使い、欠落・旧値・違うrun・採用途中なら30Gを残す。既知の60G等は全額を残す。
主人公の修復予約も追加で残す。選択や確認Aだけで回復・消費を作らない。

正しい同月取引から静かな月メニューへ戻り、本人の実見積50Gと実残金差が一致した
場合だけ、その人の支払いを記録する。他人の卵数量・再確認・既知の0は解除しない。
支払った本人も数量を未知にし、後の本人実正数でだけ0禁止を解除する。同じ月の
本人への二重支払を避け、未支払いの他人の50G予約を保持して兵士へ回さない。
残金が許せば次の人も同じ実見積・実支払いを経て回復し、足りなくなれば次月へ待つ。

確認後の見積のフェードは別の買い物として再決定しない。既存の月取引・儀式の
有限観測予算を使い、再起動や強制終了、共有配信・音声・ユーザー休止の変更は行わない。

検証は合成一覧/見積/月メニューの状態遷移と、既存の元回復画面・同月完全賃金・
支払復帰の回帰で行う。v176の本番個別回復は未受入。正規PR/fresh review・CI/main/
canonical gateway後に対象SHAと同ランのplan/元RGB/同ID入力・実支払いを別々に確認する。

Runtime checklist: worker/queue/registry構成変更なし、既存同run hotload。構造化証拠は
個別actor/見積/実paidのみ、diagnosticsの固定version176とredactionを追加。未知/別run/
別月/価格不一致/複数個/支払欠落/再選択/二人目/賃金境界の対照を持つ。
