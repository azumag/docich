# PAPER → LIVE の自動昇格（Issue #3623 §2.6）

2026-11-27 のオーナー決定で、PAPER の銘柄別スロットの戦略を、条件を満たしたら LIVE へ自動で入れ替える。
判定は [`src/docich/trading/live/promotion.py`](../../src/docich/trading/live/promotion.py)、
適用は LIVE ワーカー（[`runner.py`](../../src/docich/trading/live_worker/runner.py) の `_promotion_step`）が行う。

## 条件（すべて満たしたときだけ）

1. **ルール v4**（[`promotion_shadow.py`](../../src/docich/trading/promotion_shadow.py)）：セル（スロット実験 × 銘柄）の e-process が E ≥ 5、日ブロック 5 以上。使うのは `paper-cost-v3` 以降の約定だけで作った `return_blocks_v3` であり、v2 以前の終値約定のブロックは使わない。日付による足切りはしない。
2. **LIVE を上回る**：そのセルの日ブロックと同じ日について、`候補の日ブロック − LIVE の日ブロック` の平均が正。LIVE の日ブロックは、その銘柄の LIVE の売り 1 件ごとの純リターン（手数料込み、平均取得原価）の日平均。LIVE がその日に売っていなければ 0。
   LIVE がまだ扱っていない銘柄は、1 だけで追加する。
3. **頻度**：その銘柄の LIVE 方針が変わってから 7 日未満なら変えない（初回登録・昇格のどちらも数える）。つまり 1 銘柄 7 日に 1 回まで。
4. **停止**：`<state_dir>/trading-live/owner/promotion.disabled` があれば判定も適用もしない。新規の買いを止める安全装置が作動中も昇格しない。
5. **ルールの出所**：セルの実験そのもの（スロットの `paper_strategy_experiment.json`、交代済みならスロットの評価履歴）。厳密な往復検査と LIVE の範囲（JPY 建て、1 回の買いは資金の 30% まで）を通ったものだけ。

## 動作

- ワーカーは起動直後と、その後 1 時間ごとに判定する（サイクルの合間）。
- 昇格は LIVE 台帳に `reason=promotion`・`actor=promotion_judge` の方針の有効化として記録され、根拠の digest も残る。ワーカーはその場で新しい方針に切り替える（再起動しない）。
- 昇格で銘柄を外すことはない。置き換えか追加だけ。
- 保有中の建玉は、**買ったときの方針の売り条件**で手じまいする（`decide.entry_exit_policies`）。その銘柄の新規の買いは、旧建玉が無くなるまで止まる（既存の `legacy_position_open`）。
- 判定の結果は `<state_dir>/trading-live/promotion_status.json`（0600）。`status`（`ok` / `stopped` / `safety` / `unavailable` / `failed`）、昇格した銘柄と根拠（E、ブロック数、候補と LIVE の平均）、見送った理由（`not_better_than_live` / `min_hold` / `rules_unavailable` など）。
- 判定が壊れても売買は止めない（状態ファイルに `failed` を書き、今の方針で続ける）。

## 止め方

```bash
touch <state_dir>/trading-live/owner/promotion.disabled
```

再開はこのファイルを消す。ワーカーの再起動は要らない（次の判定から効く）。

## 既知の限界

- 比較の単位は「売り 1 件あたりの純リターンの日平均」で、資金あたりの損益ではない。
- PAPER の日ブロックは、`paper-cost-v3`（板の VWAP＋テイカー手数料）の約定だけで作った `return_blocks_v3` を使う。v3 反映前の終値約定は、スプレッドを払っていないため昇格の根拠にしない。
- ルール v4 の保証は「実質トントン以下のセルが昇格する確率はセルごとに 1/5 以下」まで。多くのセルを順に見るので、偶然の昇格は混ざる。
- v3 反映直後は v3 の約定が無いため、5 日分の日ブロックが溜まるまで昇格は起きない（意図した挙動）。

## 暗号通貨コーナーでの発表（2026-11-27 オーナー決定）

PAPERコーナーは「暗号通貨コーナー」になった（表示名・配信タイトル・次回予告・画面見出し。内部ID `paper` / `paper-view` は変えない）。
ナレーションは9枠で、`result`（PAPER：仮想資金。自由戦略の候補の成績も含む）の次に `live`（LIVE：本番の資金）が入る。

- LIVE の数字は [`corner_live_facts.py`](../../src/docich/trading/corner_live_facts.py) が LIVE 台帳を読み取り専用で開いて作る（WebUI と同じ集計）。
  円の金額（累計と今日の実現損益、銘柄別、保有の投入額）、決済件数、直近の自動昇格、安全装置の作動を出す。注文・約定・建玉のIDや残高は出さない。
- 台本は「ここからは本番の実際のお金の結果です」と分かる一言から始め、PAPER と LIVE を足したり同じものとして比べたりしない。
- コメント返答（`comment/paper_corner_profile.py`）は画面の数字（PAPER）だけを使い、LIVE の金額は作らない。

## 自由戦略の LIVE（2026-11-27 オーナー決定）

AIが書いた Python の自由戦略も、PAPER で成績が認められれば LIVE で売買する。

- **PAPER 側の昇格**：毎日の改善（`docich free-strategy improve`）が、ルール `free-v1`（日次評価額リターンの e-process、E ≥ 5・5日以上）を満たし、
  今のミラーを同じ日で上回る候補を、**LIVE ミラー**として起動する（365日、研究用の2枠の外。ミラーの入れ替えは7日に1回まで）。
- **銘柄数**：自由戦略の方針に固定の銘柄数上限はない（空でなく重複なしのJPY建て）。投入上限は従来どおり `FREE_MAX_FRACTION`（30%）と流動性の `entry_block` で、銘柄数では制限しない。
- **ミラーの保有比率**：自由戦略ワーカーが毎サイクル、ミラーの銘柄ごとの「保有の評価額 ÷ 評価額合計」を
  `<state_dir>/trading/free-strategies/live_weights.json` に書く。**AI のコードは自由戦略ワーカー（gVisor）だけで動き、取引キーを持つ LIVE ワーカーでは動かない。**
- **LIVE 側の採用**：LIVE ワーカーの昇格判定（1時間ごと）が、新しい（15分以内の）比率ファイルのミラーを自由戦略の方針として台帳に記録する（方針セットの `free` 枠。
  銘柄別の方針は変えない）。停止スイッチ `promotion.disabled` と安全装置は宣言型と同じく効く。
- **売買**：銘柄別戦略の注文のあと、残りの資金で、`比率 × C`（C は口座の資金。専用の資金枠は無い）に向けて足りない分を買う（1回は C の 30% まで、差が C の 0.5% 未満なら買わない）。
  ミラーが持たなくなった銘柄、前の自由戦略の建玉は全部売る。目標より多い分は減らさない（簡略化）。
- **同じ銘柄**：銘柄別戦略と自由戦略は同じ銘柄を別の建玉として持てる。同じ銘柄・同じ向きの未約定注文は口座全体で1つまで（台帳の制約）。
- **損失ストップ**：昇格した時点の C を基準に、その自由戦略の結果（売買の収支＋保有の直近終値評価）が基準の −10% に達したら、新規の買いを止める（売りはミラーに従い続ける）。
  次の昇格（新しい方針）で解除される。状態は `<state_dir>/trading-live/free_strategy_state.json`。
- 比率ファイルが無い・壊れている・古い・別のミラーのものなら、自由戦略の買いもミラーの売りもしない（前の方針の建玉の売りは続ける）。
