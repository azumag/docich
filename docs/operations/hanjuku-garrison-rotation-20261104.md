# 敵城に近い城を厚くする将軍の再配置（2026-11-04 オーナー指示）

## 指示

> 人数の少ない城は陥落しやすいので、積極的に将軍をまわすこと。敵の城に近いほど
> 優先度をあげる。敵の城に遠い城は一人もしくは０人でも良い。

半熟英雄の防衛戦は、城の将軍一覧の先頭から1人ずつ戦う。同じ城に将軍が少ないほど
守り切れる可能性が下がるため、将軍を後方に滞留させず、敵城に近い城へ回す。

## 変化

- 所有城ごとに、最寄りの敵城（未占領の通常城・ボス城・第4話の四季王城）までの
  マンハッタン距離を出し、目標人数と下限を決める（`orders._garrison_plan`）。
  - 最前線（最短距離の城）: 3人
  - その次の輪: 2人
  - それ以外: 1人
  - 最前線の1.5倍以上遠い城だけは0人まで送り出してよい。
- 目標に届かない城へ、より遠い城の余剰将軍を移す候補を作る
  （`replan._garrison_rotation`）。
  - 余剰（自分の目標人数を超える将軍）を持つ城を先に使う。
  - 余剰が無いときだけ、遠い城の最後の1人を前線へ回す（0人になる）。
  - 本城は主人公の隣に2人残す既存の `HERO_CASTLE_GUARD` を守る。
  - 過去に落ちた城・守備崩しで失った城は空にしない。
- 実測済みの将軍一覧がある城だけを送り元・送り先にする。送り先の到着を
  まだ一覧で読んでいない間は、同じ城へ二重に送らない（#3037）。
- 攻撃・奪還・空城の補充・ボスへの波状を先に確保し、残った余剰だけを回す。
  候補の並びも攻撃の後ろに置き、出撃を妨げない。
- 第3話は既存の道（`routes.allowed`）に沿う移動だけを作る。

## 確認の仕方

`bot_version` が v379 になったあと、判断ログで:

- `chart_interim_order` / 計画の指示に `purpose=move` かつ
  `garrison_rotate` の候補が現れ、送り元より送り先の敵城距離が短い。
- 前線の城の将軍数が増え、遠い城が1人または0人になる。
- 攻撃・奪還の候補が回転に置き換わらない（攻撃が先、回転が後）。
- 同じ城へ到着未読のまま2件目の移動を出さない。

回帰テストは `tests/test_hanjuku_garrison_rotation.py`。
