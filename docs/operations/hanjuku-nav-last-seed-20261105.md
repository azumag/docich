# 地図フレームで連続性レコードを必ず作る（v435、2026-11-05）

## 症状（実測）

- policy の `cursor` が **[392,144] のまま数時間**、`nav_last` は **null**、`uncertain` は true。
- その結果、ボス出撃指示（オケアナ→ボス）は**出撃元へ歩き出せず**、`source_miss` だけが増えていた。
- `map_step` は動いており（`map_step_seen` 15、カーソル無しは0回）、カーソル自体は見えていた。

## 原因

`update_world` は位置を積分するために前フレームの記録（`nav_last`）を使うが、この記録を
**書くのは `nav_step` が方向を計算し終えた後だけ**でした。一度でも早期 return すると
`nav_last` は null のまま固定され、以後どのフレームも積分できません（鶏と卵）。

## 変更

- `update_world`: `nav_last` が無いフレームでは、その場の観測（画面カーソル・tick・画面種別）で**必ず作る**。
- これで次の地図フレームは `NAV_CONTINUITY_TICKS`（30）以内なら積分でき、凍結が解けます。

## 検証

- `tests/test_hanjuku_nav_continuity.py` を4件に拡張: 記録が無いフレームで作られる／
  その記録で次のフレームが積分できる／30 tick 以内は積分／31 tick 以上は積分しない。
- 関連（`chart_bot` / 層）339 passed。
