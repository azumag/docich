# 将軍が1人の城から出撃計画を作らない（v516、2026-11-08）

## 事象

g1153 2026-11-08 13:30、第3話で `メガパタ` の駐留が `チコリ` 1人だったのに、
「暫定: ドンダムへの中継としてアルマムーンへ移動」という出撃計画が立った。
ゲームは最後の1人を出撃させられないため、実行時に一覧を読んで取り消された。
オーナー指摘:

> 将軍が一人しかいない城からの出撃計画がたち、城に一人残すというルールと矛盾してしまっている。

## 原因

- 機械計画の第3話中継移動は `routes.probe_due` を使っていた。これは輸送が
  **まだ行軍中**でも真になるため、増援が着く前の1人城から移動計画を作っていた。
- 単将軍の城からの到着確認は「出撃注文」として作られ、実行時の
  `_keep_sortie_defender` / `_move_general_pick` が取り消すだけだった。
  計画・実況の上では出撃計画に見え、ルールと矛盾していた。

## 変化

- 中継移動の到着確認は `routes.arrival_probe_due`（行軍のbusy window通過後）に
  変えた。行軍中は計画を作らず、到着の可能性があるときだけ一覧を開く。
- 実測で1人しかいない城からの到着・新入り確認は **読取専用の roster probe**
  にする（`roster_probe`）。
  - 一覧を開いて駐留を記録し、将軍を選ばずに戻る。出撃はしない。
  - 一覧の実測で2人以上になった次の計画から、通常の移動・攻撃として出せる。
- 機械計画の step 名は probe 専用に分ける（`source>target:purpose:probe:<輸送tick>`）。
  probe が `done` になっても、確認後の本番出撃が同じ step を引き継いで
  起動不能にならないようにする。
- 採用済み計画（LLM調整チャートを含む）でも、単将軍の城の `source_probe` は
  読取専用に落とす。
- 実況は probe を「メガパタ城の将軍一覧を読んで、増援が着いているか確認します。」
  と読み、出撃準備として読み上げない。計画サマリも「メガパタの一覧確認」と表示する。
- 一覧を読んでも新入りが見つからなければ、その城の未配置将軍の推定を棄却する
  （同じ1人城を同じ根拠で繰り返し読まない）。

## 確認の仕方

`bot_version` が `hanjuku-chart-v516-singleton-roster-probe` になったあと:

- 判断ログの `order_start` が `roster_probe: true` で、`reason` が
  「〜の将軍一覧を読んで増援の到着を確認する」になっている。
- 駐留1人の城を出撃元にした `purpose=move/attack/retake` の指示が
  `chart_plan` に残らない（probe を除く）。
- probe の実行後、`garrison_seen` で駐留が更新され、2人以上なら次の計画で
  通常の出撃・移動が始まる。
- 行軍中の輸送がある間は、その城を出撃元にした計画が立たない。
