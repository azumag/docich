# 半熟英雄: 自城へ送った増援の到着を、行先の城一覧で確認する（v760、2026-11-13）

## 症状（実測 g1163 2026-11-13 12:30〜13:03）

第9話で `オオキク` を失い、`ドンドン` から奪還するため `オシロガ` から
増援を送り続けていました。12:30〜12:52 に **10人以上**が
`オシロガ>ドンドン` へ出撃し、出撃元の一覧で「本人がいない」ことまで確認
されています（`sortie_launch_confirmed` ジキタリス / サフラン / ヘラ / ギー /
バーミセリ / ドリアン / マンゴスチン / バトウラ / デーメーテール ほか）。

ところが `world.garrison['ドンドン']` は **1人（ヘパイストス）のまま**。
`front_wait_mass` は「在城3人」を待ち続け、900 tick で単独攻撃へ戻る寸前でした。

### なぜ到着が見えないか

- 自城への移動は全体マップに部隊▲が出ないため、到着は**行先の城一覧**でしか
  観測できません（`sortie_move_overdue_settled` の既存コメント）。
- 行先 `ドンドン` の一覧を開くのは、`ドンドン` から出撃するときだけ。
- v757/v759 の2人待ちが `ドンドン` からの出撃を保留したため、**行先の一覧を
  読む機会がなくなり**、到着済みの増援が `garrison` に反映されない。
- `_roster_probe()` は「枯渇マークの付いた城」しか巡回対象にしておらず、
  移動を受け入れた城（`routes.probe_due`）を見ていませんでした。

## 修正（v760 `hanjuku-chart-v760-destination-roster-probe`）

`corridor._roster_probe()` の巡回対象に、**移動を受け入れた城**
（`routes.probe_due(mem, castle)` が真の城）を加え、枯渇巡回より優先します。

- 行先の一覧を1回開くだけで、`routes.observed_roster` が到着を記録し、
  `garrison` が実際の在城者（例: 6人）に更新される。
- 2人待ちはその在城者を見て、3人以上なら奪還の2人同時出撃に進む。
- 同じ城を短時間に何度も読まないのは `routes.probe_due` の
  `PROBE_INTERVAL` が担保する。
- 枯渇マークの巡回（v758 で名前ベースに制限）は従来どおり。

## 検証

- 新規 `test_a_castle_a_transfer_was_sent_into_is_read_first`:
  drained が無くても、移動を受け入れた前線城の一覧を読むプローブが出る。
- 第9話 corridor / 派遣 / 城ルート / 前線 / capture guard 関連
  **164 件 passed**。
- 修正前の `corridor.py` では新テストが失敗することを確認。

## 本番反映後に実測すること

- `roster_probe` の `mint_order.source` が `ドンドン` になり、行先一覧が
  読まれること。
- `world.garrison['ドンドン']` が実際の在城者（複数）に更新されること。
- 続く `front_wait_mass` が解除され、`オオキク` へ2人以上が同時に出撃すること。

## 残件

- 行先一覧を読んでも在城者が増えていない場合、移動自体が途中の戦闘で
  失われている。その場合は道路の戦闘・再出撃の経路を別途直す。
- 第9話の進行と12話ボス撃破は引き続き実測で確認する。
