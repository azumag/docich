# 兵士20人以下の月は補充を最優先する

2026-10-17のオーナー指示「半熟兵士が20人以下のときは、卵や将軍、切り札より補充を最優先にする」を実装する（v232、`hanjuku-chart-v232-low-army-refill-first`）。関連: #2366（16人で募集・築城が先になる報告）。

v244（#2367）で必要支出の給与留保を0Gへ変更。#2611の給与確認待ちだけで補充を止めない修正も維持する。

## 判断

同一実行・章・月で実兵数を確認でき、20人以下（`LOW_ARMY`）の場合、月一メニューでは兵士補充を先に行う。

- 補充予算は所持金から**家での卵修理費**（主人公・将軍の `*_repair_reserve`）だけを残した額。卵回復の予約（`reserve`）、将軍募集費（`recruit_reserve`）、未購入の切り札（商人で買う予定のカード）は差し引かない。
- 補充人数は従来の目標人数（通常50人、余裕資金があれば約100人）までの不足分。全額がなければ買える人数を補充する。
- 補充を確定するまで、しょうにん（切り札購入）・たまごのかいふく・しょうぐんぼしゅうを開かない。主人公の卵が減っている月も同じ。
- 将軍募集は従来の0人時と同じく当月は見送る（`recruit='deferred_army'`）。卵回復は見送り扱いにせず、`egg='pending'` と卵予約・残数・再確認履歴を保持する。
- 補充の支払いを確認した後（`soldier_receipt` あり）は優先を解除し、残金で従来の順（商人→卵回復→築城）に進む。商人は従来どおり給与留保と必要予約を守り、卵回復は給与留保0Gで実費と家修理予約を照合する。
- 21人以上、兵数が未読・前月・別実行・別章の場合は従来の順序と予算のまま。

## 支払いと有限性

- 優先状態は `shop['low_army_refill']`（`version: 1`・scope・実兵数・補充人数・`active`）にJSON保存し、毎回の月一メニュー観測で再検証する。兵数が古くなった・支払いreceiptができた・儀式中・募集の支払い未確認・兵数確認の失敗では `active` を外す。
- 数量画面では保存した `active` だけを根拠にし、卵予約の再計算や未購入の切り札・家修理の予約で補充人数を削らない。支払上限は `_soldier_spendable`（給与留保0G、修理費を残す）で再確認する。
- 実人数の確認・補充要求・数量入力・支払照合は既存の `army_count_check` と `soldier_refill_receipt` の有限上限を使う。A入力や計画だけで補充完了とせず、確認失敗後に補充を再開しない。
- 卵回復見送り後の補充（`soldier_egg_deferral`、[既存仕様](hanjuku-soldiers-after-egg-skip.md)）が有効な月はそちらを優先し、二重に計画しない。

診断イベントは `low_army_refill_plan`（旧 `zero_army_refill_plan` を一般化）。`observed_metric` に実兵数・所持金・補充人数・手元に残す額・後回しにした卵予約と切り札を記録する。
