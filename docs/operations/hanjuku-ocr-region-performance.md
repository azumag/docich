# 半熟英雄: OCR領域走査の縮小

## 範囲

`read_lines` が矩形内の文字だけを要求する場合でも、従来は毎回256×224全画面の
色predicateを評価していた。暗色の戦闘パネルと灰色の無効メニュー読み取りで、
必要な矩形と濁点・半濁点用の上8行だけを走査する。

- 行maskは元の画面座標・ビット位置を維持する。x開始は8px境界へ切り下げる。
- 濁点が指定矩形の外側にあっても保持する。全画面要求と呼び出し元から渡された
  maskの再利用は従来どおり。閾値、文字照合、未知文字、縦offset探索を変えない。
- ゲーム戦略、カーソル入力、hold時間、通常1500ms/近接戦闘500msの観測周期は
  変更しない。認識処理のCPU負荷を先に減らす段階であり、実機のテンポ改善を
  測定済みと扱わない。

## 検証

`tests/test_hanjuku_font_regions.py` は全画面の従来mask生成と、切り出し後の
文字列/位置/未知文字を比較する。8種類の縦offset、非整列x、矩形外の濁点・
半濁点、dark/light/gray predicate、端部、deterministic noiseを含む。
狭いメニュー `(176,176,256,216)` ではpredicate呼び出しが57,344から3,840へ
減ることを決定的に検証する。これはCPU使用率やゲーム全体の速度の測定ではない。

2026-09-30のwagyuクラウド上の合成フレーム・10回×3組の中央値では、
同矩形の`read_lines`が全画面mask使用時16.056msから領域mask使用時1.562ms、
戦闘パネル `(0,160,256,200)` が16.677msから5.015msだった。
これは同じ結果を返すOCR部分だけのマイクロベンチマークであり、VM上の実画面、
キャプチャ、プロセス起動、入力待ちを含まない。閾値付き速度テストにはしない。

次段階は実環境のcapture/認識/判断/入力/待機の内訳とCPU負荷を比較すること。
その根拠を得るまで、ポーリングを一律に高速化しない。

## 読めたメニュー移動の再観測（v196）

終了済みg745の元8064（召喚獣の1行目）→8065（2行目）は、同decision/RGB入力down→Aを照合でき、action_plan間隔は1513msだった。会話8128には実選択肢がなく、旧parserが絵の9ピクセルから騎士カーソル167を返す。元3PNGと手で確認した正解を `tests/fixtures/hanjuku/g745-menu-reading-evidence.json` に保持する。

- 騎士カーソルは実コマンドか完全な既知カード行に対応するものだけを使う。同点の候補は未読とする。タイトルのない実カード一覧（g684/g692）のカーソルは保持する。
- ヘッダーは上部の同じ行から、数字の間の未知字形・空白を残して年/月/Gを読む。131Gの中央字形を欠かせた合成対照を11Gと読まず未確認にし、別行・重複のヘッダーも結合しない。元85PNGの既存ヘッダー値を維持した。完全に消えた先頭数字と元々短い金額の区別はこの変更だけでは証明できない。
- 実コマンド画面では地図G/白角カーソルの全画面探索を省く。城・出撃・カード選択の背景地図は従来通り読む。色の許容幅・完全字形一致・未読の扱いを緩めない。
- 読めたカーソルと同列の実選択肢がある前面で、up/downを単独16..100msだけ計画した場合、次観測を1500msから既存の許可値500msへ短縮する。A/B・長押し・複数操作・暗転・未読・別stepは通常間隔。新しいキーや購入/出撃の確定は作らず、到着は次の元画面で確認する。観測ごとに読み取り情報を置換し、action_planへ根拠と原RGBを残す。

ローカルparse単体（基準0be9930d、各9回中央値、元256×224、classify後のphaseを渡す）の測定:

| 元画面 | 旧parse | 新parse |
| --- | ---: | ---: |
| g745召喚獣1行目8064 | 62.1ms | 24.9ms |
| g745召喚獣2行目8065 | 61.9ms | 24.5ms |
| g713白兵パネル | 36.7ms | 28.8ms |
| g741月初人数確認 | 22.8ms | 19.2ms |

85PNGの比較は既存出力の退行確認であり、全85枚の独立正解ラベルや認識精度率ではない。上の時間はVM capture・起動・入力送信・待機を含まず、自然runの操作速度や勝利は未受入。配備後は同runtime/gen/leaseの新version plan・原RGB・同ID/current frameSHA入力と次の実カーソル行・実間隔を結合して別に確認する。
