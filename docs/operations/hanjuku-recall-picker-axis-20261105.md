# 帰還ピッカーのカーソルが動かないとき片軸しか試さない（v393、2026-11-05）

## 症状

撤退した将軍を城へ帰す「きかん」の全体マップピッカーで、目標の城へカーソルが
動かず、15観測かけて別の城（今いる城）へフォールバックすることが繰り返された。

g1133（第6話、2026-11-05）の実測:

| 時刻 (JST) | 結果 |
| --- | --- |
| 00:14:49 | ダーラントへ向かうカーソルが バビラリー で停止（still 8）→ 取消 |
| 01:06:35 | 同じく停止 → バビラリーへフォールバック |
| 01:28:12 | 同じく停止 → バビラリーへフォールバック |
| 01:33:19 | 同じく停止 → バビラリーへフォールバック |

3.5時間で `camp_recall_picker_step` 70件・`camp_recall_cursor` 20件。
4回の帰還指示のうち3回が目標と違う城で確定した。

## 原因

`world_map_step` のピッカー操作は、目標との差分が大きい軸を主軸にして押し、
カーソルが `PICKER_AXIS_SWITCH`（2）回動かなければ「もう一方の軸」へ切り替える。
しかし切り替えの条件が

    still >= PICKER_AXIS_SWITCH and min(abs(dx), abs(dy)) >= 3

で、もう一方の軸の差が3px未満だと切り替えない。バビラリー (73,120) から
ダーラント (111,119) は dx=38, dy=-1.5 で、主軸の「右」を8回押しても
カーソルが動かず、上下は一度も試されなかった。

## 修正（v393）

- もう一方の軸の差が3px以上なら従来どおりその軸へ切り替える。
- 3px未満のときは、`PICKER_AXIS_SWITCH` 回ごとに主軸と副軸を交互に押す
  （右・右・上・上・右・右…）。動けば `still` が0に戻り、通常の操作へ戻る。
- 上限 `PICKER_STILL_LIMIT`（8）と、動かない場合に今いる城で確定する
  フォールバックは変えない。

## 確認の仕方

- `bot_version` が v393 になったあと、`camp_recall_picker_step` の
  `press` が主軸と副軸で交互になり、`camp_recall_picker_fallback` が
  減ること。帰還先が目標の城になること。
- `tests/test_hanjuku_recall_destination.py` が、副軸の差が小さいときに
  軸を交互に試すこと、差が大きいときは従来どおり副軸を押し続けることを
  確認する。
- 実プレイでの成立は配備後の実観測で確認する。テストの成功を実機の成立とは
  扱わない。

## 未確認

- ピッカーが城から城へどう動くか（道路沿いか、固定順か）は未解明。今回は
  「動かない軸を押し続けない」ことだけを直した。上下でも動かない場合は
  従来どおり今いる城で確定する。
