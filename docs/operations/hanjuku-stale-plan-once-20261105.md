# 計画の再構築記録が毎観測繰り返されるのを止める（v409、2026-11-05）

## 症状（実測）

v406 で入れた「長時間未発射の計画を捨てる」ガードが、実機で**同じ記録を繰り返した**。

- `plan_stale_rebuild` が30分間に **87件**。
- すべて同じ計画（`A:bf8c3dee:M256898` / `Ma21426` / `M22c018`）で、`age` も 789 で同一。
- 併せて `chart_adjust_applied` が30分に116件、`y_jump_open` が121件と再構築の連鎖が続いた。

## 原因

計画を捨てても、別経路が同じ計画を戻すため、次の観測でまた「古い計画」と判定され、
記録と破棄を毎観測繰り返していた（破棄が定着しないケース）。

## 変更

- `_drop_stale_plan` は計画の step 列を署名として覚え、**同じ計画では二度目以降は何もしない**
  （記録も破棄もしない）。
- `_adopt_plan` で新しい計画を採用したら署名を消す（次の計画は判定対象に戻る）。

## 検証

- `tests/test_hanjuku_plan_stale.py` に回帰テストを追加: 同じ計画が戻ってきても記録は1件のまま。
- 修正前は失敗、修正後 5 passed。関連（`chart_adjust` / `order_start_backoff` / 層 / `chart_bot` /
  `off_chart` / `mechanical_conquest`）を含め 424 passed。

## 未確認・残件

- 実機で `plan_stale_rebuild` と `chart_adjust_applied` の増加が止まるかは未確認。
- 破棄が定着しない原因そのもの（同じ計画を戻す経路）は未特定。署名ガードで増殖は止めるが、
  次ラウンドで経路を特定する。
- 第6話ボス城への入城は依然として未実測。
