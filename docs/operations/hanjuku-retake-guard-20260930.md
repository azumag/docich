# 奪還の重複出撃と守備維持（v109）

ユーザーから、城が一つ失われると同じ奪還先へ複数の将軍が出て、出撃元が空になり再び落城するとの指摘がありました。コードでは既に部隊が向かう城を候補の末尾へ移すだけで、出撃元の待機将軍が2人以上の城を優先するだけでした。これは重複出撃・最後の守備将軍の出撃を防いでいません。

## 動作

- 暫定候補から、最近の出撃がある行先を除きます。未確認の目標選択が割り込まれた場合は保存された指示の行先も予約します。予約は到着・占領・実際の行先の確認とは区別し、実行状態を書き換えません。
- 予約は既存の400観測期限までです。終了・失敗、時刻不明、未来、期限切れの記録を新たな予約にせず、古い未確認到着で永久停止しません。
- 奪還と暫定攻撃は、出撃元に待機将軍を1人残せる場合だけ選びます。出撃中・所在未確認の将軍は守備に数えません。卵が壊れた主人公は出撃候補から外しますが、待機している守備としては数えます。
- 記録だけでなく実将軍一覧でも確認し、1人以下・重複名で水増しされた一覧から確定Aを送りません。読めない一覧は保留します。ホットロード前の選択途中も、他部隊への奪還予約・不足した守備記録があれば取り消します。
- 通常チャートでも、失った城の奪還指示には同じ制約を適用します。待機に戻した指示が空城への配置・募集を妨げないよう、実行可能な計画の判定にも反映します。
- 既に発行した未確認出撃の携行札・照合経路、原典の初回攻撃、ボスへ送る原典の連続部隊は維持します。ゲーム・共通配信・音声を再起動しません。

## 検証と限界

重複予約、途中で行先未確認、期限切れ、実一覧の1人/空/重複名、出撃済み将軍、選択途中へのホットロード、通常チャート奪還の待機解除、原典・ボス除外を回帰検証しました。既存の「単独将軍を暫定攻撃へ送る」「予約済みの城を末尾に残す」期待は今回の仕様に更新しました。卵の壊れた主人公が守備に残る既存ケースも維持しています。
