# 帰還ピッカーが2城の間を往復し続ける（v396、2026-11-05）

## 症状

撤退した将軍を城へ帰す「きかん」の全体マップピッカーで、カーソルが2つの城の
間を往復し続け、帰還指示が完了しない。

g1133（第6話、2026-11-05）の実測:

| 時刻 (JST) | 出来事 |
| --- | --- |
| 02:13:55 | ダーラントへ帰還の指示を開始（カーソル 111,62） |
| 02:20:19 | バビラリー (73,120.5) で right → オケアナ (175,90.5) へ |
| 02:20:23 | オケアナで left → バビラリーへ戻る |
| 02:20:28-02:22:41 | right/up/left/down を交互に押して同じ往復を繰り返す |

9分以上、`camp_recall_picker_step` だけが続いた。

## 原因

v393 で「主軸が動かないときは副軸も試す」ようにしたが、ピッカーの移動は
方向に比例せず、右で隣の城へ移り左で戻るため、副軸を混ぜても2城の往復になる。
`still`（同じ位置に留まった回数）は移動のたびに0へ戻るので、
`PICKER_STILL_LIMIT` のフォールバックが発火しない。

## 修正（v396）

- 直近 `PICKER_HISTORY`（4）件のカーソル位置を覚え、同じ位置を再訪したら
  `picker_loops` を1つ進める。
- `PICKER_LOOP_LIMIT`（3）回到達で、動かない場合と同じフォールバック
  （今いる城で確定）へ進む。
- 1歩が `PICKER_LOOP_MIN_STEP`（8px）未満の細かい揺れは往復と数えない
  （移動中のジッターで早々に諦めないため）。
- 敵城の上で止まった場合の取り消しも同じ条件で判定する。

## 確認の仕方

- `bot_version` が v396 になったあと、帰還ピッカーの
  `camp_recall_picker_step` の `loops` が増え、数回で
  `camp_recall_picker_fallback` → `camp_recall_requested` に進むこと。
- `tests/test_hanjuku_recall_destination.py` が、2城の往復で
  `PICKER_LOOP_LIMIT` 回到達時にフォールバックすること、細かい揺れでは
  諦めないこと、v393 の軸交互操作が残ることを確認する。
- 実プレイでの成立は配備後の実観測で確認する。

## 未確認

- ピッカーの移動規則（方向比例か、城の順序か）は未解明。今回は往復を
  有限回で打ち切ることだけを直した。
