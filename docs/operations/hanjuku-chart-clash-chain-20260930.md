# チャートの札条件と連携観測を復元

ownerの2026-09-30指摘「チャート通りの切り札を持っていたら、チャート通りにやったら卵を使わせないで倒せる」に対応する。

第1話の実チャートは「白兵で一回ぶつかり合う→すぐにクースカン→続けてノリウツール」。[GCGX第1話攻略](https://gcgx.games/hanjuku/01.html)にも同じ手順が記載されている。g486はクースカンを衝突前に前倒しし、90対70から90対35となった後に後続Bを計画したが、次画像は敵の卵使用でノリウツールの選択は成立しなかった。v88の卵回復待ちはこの札手順の不履行を解決しない。

v89はafter_clashとHP閾値札を開幕に前倒しするロジックを除去する。チャートで指定した衝突後・HP条件・札順序を維持する。既存の衝突証拠は同じ将軍の明瞭なHPパネルで敵HPが開始値より低下したこと。入力計画だけから衝突を推定しない。クースカンを選択した後の敵HP減少で後続Bへ進む既存の即時連携を維持する。未校正の使用告知は未分類のままで、選択と消費を同一視しない。

札入力中に観測間隔が1500msに戻っていたため、生存HPが正に確定している白兵とそのcard_flowのbattle/menu/text/unknown遷移で既存の500msを維持する。マップ、卵戦、死亡/HP未知パネルは短縮しない。accepted protocolの500/1500以外を追加せず、worker/agent loopの入替は不要。

回帰1133passed/1skipped/1deselected。未取得submodule実知識検査のみ環境不足として除外。衝突前は白兵、HP低下後にクースカン、後続ノリウツール、HP条件札の閾値前後、札入力の3段階と4種類の画面で500ms維持を確認。自己レビューのみ、独立レビュー未実施。実ゲームの連携成立・敵未召喚・勝利は未確認で、同一g490ランへのcanonical配備/ホットロード後に実画面とログで確認する。

runtime manifest、worker health、queue registry、providerを変更しない。既存のbattle_card/melee/action_planのstructured telemetryとdiagnostics契約を利用する。secretやprompt本文を出力しない。対象旧ファイルはignored run/hanjuku-live-watch/hanjuku-v89-before.tarに退避。tracked production filesを直接編集せず、PR・最新CI・protected main・canonical Actions deployに従う。
