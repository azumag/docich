# 行軍中断の戦闘でおくのてを使えなかった（v1453、2026-11-24）

## 症状

g1342 第3話。13:10〜13:22 JST の敗戦で `battle_okunote_risk_declined`
（低HPだが既存保護条件があるため奥の手を開かず白兵へ戻る）が続き、
パプリカ（HP34、卵なし、携行札なし）、デュオニソス、キャンディー、ヘルメスが
白兵で敗北した。おくのて自体は 12:50・13:07 の守備戦では使えていた。

## 原因

1. 保護判定が**メニュー行の見た目**を根拠にしていた。`たまごをつかう` /
   `きりふだ` の行は卵・札が無くても常に描画されるため、
   「使用可能な卵/切り札がある」と誤判定していた。パプリカは
   `has_egg: false`・携行 `[]` だった。
2. 保護判定と `_defender_last_resort` が `side == 'defense'` を要求していた。
   行軍中の戦闘は攻撃メッセージを伴わず `side`・`castle` が未分類（None）に
   なるため、守備戦でなく「守備と確認できない」だけで奥の手を開けず、
   敗北していた。

## 修正（v1453 `hanjuku-chart-v1453-okunote-unclassified`）

- 保護判定を `_okunote_risk_protected` に分離。
- 卵・札の保護は**実測した戦闘計画**（`cur['egg_plan']` の `has_egg` と
  使用可能な携行札）だけを根拠にする。メニューの行ラベルは使わない。
- `side` が未分類（None）の敗色戦は、実測の卵・札が残っていなければ
  おくのてを開けるようにした。**確認できた攻撃戦（side == 'attack'）と
  主人公・ボス・計画札・卵戦・召喚戦の保護は従来どおり**。
- 判断記録に `side` / `castle` を残し、次回の切り分けを可能にする。

## 検証

- `tests/test_hanjuku_okunote_unclassified.py`（新規）: 未分類・卵/札なしで
  おくのてを開く／攻撃戦は従来どおり見送る／実測の使用可能札・卵があると
  見送る／主人公は保護／行ラベルだけでは保護しない。
- 既存 `tests/test_hanjuku_defender_last_resort.py` の side=None 見送り前提を
  新仕様へ更新。
- 実機確認はデプロイ後に、`battle_okunote_risk_accepted` とおくのて選択、
  未分類戦での敗北減少を確認する。
