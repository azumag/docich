# 将軍不足時の募集費先取り

ユーザー指摘: 将軍が足りないのに兵士補充だけを続け、将軍減少でジリ貧になる。
旧ルールは2026-09-27の「兵士99人補充後、募集費50G＋賃金予備30Gが残れば募集」。
今回の指示に従い、将軍不足時はこの旧条件を置き換える。

## 実ログの根拠

全軍の総数や死亡数へ換算しない。RRPG基本情報 https://rrpg.jp/hanjuku_hero_2/basic.html
で募集50G・3候補から1人・主人公のいる城へ配置を照合した。

## v95

自軍城で観測した将軍名と直近の出撃確定済み行軍を重複なく数え、6人を確認
できない時は補充を優先する。未観測・所在不明・出撃未確定を在籍総数に捏造
しない。未読の在城一覧だけで総数不足とは断定せず、記録はcount_lower_bound/
total_roster=unclassified。城一覧の観測自体が無い時は従来順序を維持する。

原典切り札の購入費、既存卵回復費と賃金30Gを維持し、残りから募集50Gを
兵士より先取り。101G/卵費なしなら募集50＋予備30＋兵士21。79Gなら兵士0、
49Gを募集資金として温存し、築城へも流用しない。旧99人補充条件を不足時
だけ解除し、資金があれば兵士の前に募集。募集後に兵士補充へ戻る。購入後の
実所持金でも予算を照合し、未価格の札で過大な兵士予算にしない。募集済みは
再課金しない。同月cached shopへも一度だけ適用し、ゲーム再起動は不要。

支払50Gは募集処理の証拠であり将軍増加の証拠とは分ける。紹介の実候補名を
保持し、主人公が実在する城と本城の古い一覧を無効化。紹介候補が次の在城
一覧に現れた時にrecruit_join_observedで城名と名前を記録する。新将軍を
stateへ手書きしない。既存の余剰将軍移動/手薄な城への配置判断を引き続き使う。
