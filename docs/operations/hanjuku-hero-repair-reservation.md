# 主人公の修理予約を解放する条件（#2601）

v245。破損卵だけを理由に毎月50Gを保持する経路を、修理不能の新しい観測で解放する。

対象本人、正規run identity、現在章・月、観測tickが一致し、既存の在城再確認と同じ400tick以内で、HPが整数かつ最大HP未満、または移動中と実読した場合だけ解放する。単に家にいないこと、HP未読、キャンプ中、城にいることは修理不能の証拠ではない。旧保存データに観測run identityがなければ保留を維持する。月次の個別詳細巡回は追加しない。

2026-10-21のオーナー回答に従い、一度確認した修理不能による解放は、次に修理可能と確認するまで同一ラン・章内で維持する。月替わりや400tick経過、HP未読だけでは再予約しない。新月の個別詳細巡回は追加しない。この永続stateは現在のHPの推測ではなく、資金予約方針である。すでに全快していても通常のステータス観測までは補充などへ使える。

正常な本人ステータスで全快かつ在城またはキャンプを確認したら予約を復元する。卵の修理済みを確認した場合も解放stateを解除する。別ラン・章への持越しはしない。新たに解放を開始するには上記の新しい観測が必要で、古い保存データから推定しない。予約を戻すことは派遣許可を意味せず、既存の安全ルート・守備・本人・破損・実価格確認を維持する。

進行中の主人公修理（出発前の確認を含む）、購入・帰還・出発未確定state、月次の購入入力中は解放しない。一般将軍の修理、卵、募集、未購入札の予約は変更しない。任意築城の給与予備は保持する。補充・築城の主人公50G床は同じ不能判定を使う。解放額と理由は `hero_repair_funds_released` に記録する。

低兵数の既存月次優先処理により、解放した現金で必要補充を再計画できる。合成65G・兵5人・修理50Gの例では、解放後は45人分を予定し、兵士補充メニューへ進む。入力だけでは支払成立にせず、既存receipt確認を維持する。

コード・合成テストと実プレイ受入は別。自然ランで同一ラン・章の不能観測、解放理由、購入入力、支払receipt、補充後人数を照合するまでIssue完了とはしない。
