# 半熟英雄: 移動後は城のページ下限を「消さずに更新」する（v784、2026-11-13）

## 症状（実測 g1163 2026-11-13 20:2x）

前線 `ドンドン` が再び空になりました。`オシロガ` には4人の増援（ページ
読み）がいたのに、移動のたびに v777 がそのページを消していたため、
v779 の「増援がいるか」の判定が「いない」になり、v735 の1人待ち上限が
最後の1人（ドリアン）を単独出撃させていました。

```
garrison['ドンドン'] = []            ← 空
front_guard_hold  = {"ドンドン": 142230}
front_mass_count  = {"ドンドン": 0}
```

## 原因

v777 は「移動前のページが古い人数を見せる」問題に対して、移動のたびに
`garrison_partial` を**丸ごと削除**していました。しかしページの他の名前は
まだその城にいるので、削除すると増援の存在情報まで失われます。

## 修正（v784 `hanjuku-chart-v784-partial-move-update`）

`_garrison_move` は、ページを消さず**移動者だけを更新**します。

- 移動元のページから移動者を除く（他の名前は残る）。
- 移動先のページに移動者を加える（ページがある場合）。
- 完全リスト（`garrison`）は従来どおり更新する。

ページの下限としての意味（そこにいる名前の証明）を保ちつつ、移動という
確定事実を反映するので、v779 の増援判定が正しく働きます。

## 検証

- 更新テスト `test_a_move_updates_the_page_for_both_castles`:
  ペコリーノの移動で、ドンドンのページからペコリーノが消え、
  オシロガのページに加わる（他の名前は残る）。
- corridor / 前線 / capture guard / 派遣 関連 **183件 passed**。
- 修正前の `orders.py` では更新テストが `KeyError` で失敗することを確認。

## 本番反映後に実測すること

- 増援の移動後も `garrison_partial` に他の将軍が残ること。
- `オシロガ` に増援がいる間、`ドンドン` の最後の1人が単独出撃しないこと。
- 前線が2〜3人になってから2人同時の攻撃が出ること。

## 残件

- ページの tick は読み取り時のまま。v766 の tick 比較で完全リストが新しい
  場合はそちらが優先される。
- 第9話の進行と12話ボス撃破は引き続き実測で確認する。
