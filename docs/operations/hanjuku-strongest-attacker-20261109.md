# 半熟英雄: 攻撃には実測HPが最も高い将軍を先に出す（v540、2026-11-09）

## 症状

g1163 第5話 2026-11-09 07:13〜07:27 JST。最後の敵城 プトレマイス へ
**5回続けて攻撃**しましたが占領できませんでした。戦闘はすべて発生し
（`battle_result`）、こちらは ビシソワーズ 27 / セミヨン 36 のような
**HPの低い将軍**で敗走・敗北。同じ時間帯に カルーン には **ポセイドン 85**、
アルマムーン には ヴィーナス 82・ポワソン 80 が待機していました。

## 原因

`replan._interim_source` の将軍選択は `_spares(...)[0]`（在城一覧の並び順の先頭）で、
**将軍の強さを見ていません**。在城一覧はゲームの名簿順であり、強い将軍が先頭とは限りません。

## 修正（v540 `hanjuku-chart-v540-strongest-attacker`）

- `_strongest_first(mem, generals)`: `general_statuses` の `max_hp` が実測済みの将軍を
  **HP降順**で先に並べる。HP未読の将軍は名簿順のまま実測済みの後ろ。
- `_interim_source` の攻撃・奪還（および経路上の自城が塞ぐ場合の代替出撃元）で
  この順を使う。

## 安全性

- 主人公は従来どおり出撃対象外。主人公の城の守備人数（`HERO_CASTLE_GUARD`）と
  「最後の1人は出さない」規則は不変。
- HP未読の将軍は順位を上げない（推測で強いと扱わない）。
- ボスへの波状攻撃（卵ランク順）と偵察（source_probe）は対象外。

## 確認

- `tests/test_hanjuku_strongest_attacker.py`（新規3件）: HP降順の並び、HP未読は名簿順の
  後ろ、暫定攻撃が最強の将軍を選ぶ、主人公の城の守備規則は不変。
- 暫定出撃・未読出撃元・計画・ボス偵察 169件 passed。
- 本番反映後: プトレマイス攻撃の将軍が実測HP上位になり、占領までの敗走が減ることを
  実測する。
