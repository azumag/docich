# 半熟英雄: 小さな赤い飾りで出撃成立を誤認しない（v537、2026-11-09）

## 症状

g1163 第5話 2026-11-09 05:28:54 JST。出撃の成立確認で、Y ビューの
`[[121,78,127,83]]`（主人公の▲）に加えて `[[149,63,152,66]]`（3x3 の赤い飾り）を
「新しい部隊マーカー」とみなし、3件の出撃を同時に成立扱いした。
その後 06:04 以降の同じ step が `sortie_march_overdue`（行軍が入城しない）になっており、
成立していない出撃を established として扱っていた。

## 原因

`flows/map._probe_launch_markers` は「基準に無いマーカーが**どこかに**現れたら成立」
という規則（`baseline and fresh`）で判定し、マーカーの大きさを見ていなかった。
`world_markers` は 6〜60 画素の成分を通すため、3x3（9画素）の飾りも部隊と同格に扱われる。

## 修正（v537 `hanjuku-chart-v537-launch-marker-size`）

- `LAUNCH_PROBE_MIN_BOX = 20` を追加し、`fresh` の候補を
  **バウンディングボックスが20画素以上**のマーカーに限定した。
  - 実測の行軍▲は約 7x6（42画素）。
  - 3x3（9画素）の飾りは成立の証拠にならない。
- 近傍判定（出撃元・行先の旗から10px以内）と「基準に無いマーカー」の規則は不変。
  遠方の実ユニットは従来どおり成立の証拠になる。

## 確認

- `tests/test_hanjuku_departure_request.py` に2件追加:
  3x3 の飾りでは成立しない（probe は blind のまま）、
  離れた位置の実サイズの▲は従来どおり成立する。
- 出撃・行軍・Yビュー関連 246件 passed。
- 本番反映後: `sortie_launch_confirmed` の誤認（直後の `sortie_march_overdue`）が
  減ることを実測する。
