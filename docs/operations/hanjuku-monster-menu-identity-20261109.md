# 半熟英雄: 召喚獣の名前が読めなくても技名から攻撃データを引く（v589、2026-11-09）

## 症状（実測）

直近の `monster_menu_choice` 27件のうち **9件で `monster_attack_policy` が null**
（＝攻撃データによる選択が走っていない）。内訳の一つが
`menu: ['エクスカリバる', 'マサムネる', 'たまごにもどれ']` で、
攻撃データ表には **エクスカリバー** として行があります。

## 原因

`_monster_attack_policy_default` は**味方モンスター名**で表を引いていました
（`attack_data.get(ally.name)` / `_monster_display_name`）。
パネルの名前が表のキーと一致しない（表記ゆれ・余分な「る」・切り詰め）と、
技データがあるのに `None` を返していました。

## 修正（v589 `hanjuku-chart-v589-monster-menu-identity`）

名前で引けなかった場合、**実メニューの2つの技名**で表を照合します。

- 2技の名前（正規化後）が完全一致する行が**ちょうど1件**のときだけ採用（誤爆防止）。
- 一致しなければ従来どおり `None`（推測でボタンを押さない）。
- 採用時の既存ガード（メニュー2技の一致確認）はそのまま通ります。

## 確認

- `tests/test_hanjuku_monster_attack_policy.py` に1件追加: 味方名が「エクスカリバる」でも
  `エクスカリバる/マサムネる` のメニューから `エクスカリバー` の行を引き、選択が返る。
- 召喚獣攻撃・診断 13件 passed。
- 本番反映後: `monster_attack_policy: null` の割合が減り、召喚獣戦で
  データに基づく選択（全体攻撃を含む）が増えることを実測する。
