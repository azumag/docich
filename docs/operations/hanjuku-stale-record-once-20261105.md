# 計画の再構築記録をプロセスごとに1回にする（v411、2026-11-05）

## 症状（実測）

v409 の署名ガードでも `plan_stale_rebuild` が止まらなかった。

- v409 稼働12.5分で **99件**、v410 稼働直後も 9件/0.6分。
- live の policy を3回サンプルすると `chart_plan_tick` は 45090 のまま、
  `plan_stale_signature` は **None のまま**（= ガードが書いた値が残っていない）。

## 原因

計画を組み立てる経路の一部（chart worker など）が **mem のコピー**で動いており、
その中で記録だけがログへ出て、状態（署名）は捨てられていた。
そのため毎回「初めて見る古い計画」と判定され、記録が繰り返されていた。

## 変更

- `strategy/replan.py` にプロセス内の記録済み署名（`_STALE_REPORTED`、32件で有界）を追加。
  同じ計画はプロセスごとに1回だけ記録する。破棄自体は毎回行う（挙動は変えない）。
- 既存の state 署名ガードはそのまま残す（実プロセスの状態でも二重に抑える）。

## 検証

- `tests/test_hanjuku_plan_stale.py` に「コピーで署名が残らない場合も1回だけ」を追加（6件、autouse でクリア）。
- 関連（`chart_adjust` / 層 / `chart_bot`）を含め 415 passed。
