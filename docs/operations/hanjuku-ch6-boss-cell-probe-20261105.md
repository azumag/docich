# 第6話ボス城に入れないとき、目標セルを1タイルずつ試す（v403、2026-11-05）

## 症状

第6話の通常11城を制圧後、ボス（完熟秘密基地）へ8隊を出撃させたが、
1隊も入城できなかった（`boss_sortie_overdue` 2件、残りは `en_route` のまま）。

- v402 で Y ビューを実測し、チャートのボスセル (818,184) は基地の中心に
  1px 以内で一致することを確認済み。セルの「位置」は正しい。
- 出撃は成立している（`sortie_launch_confirmed` が4件、出撃元の名簿から将軍が消えている）。
- それでも入城しないため、疑うべきは「基地の中心セルが、ゲームが軍を入れるタイルではない」こと。
  g1075 では目標マーカーが建物の6px外に落ち、将軍が隣で野営したまま3000観測進まなかった。

## 変更

- `os_layer/navigation.py` に `BOSS_CELL_PROBES`（第6話のみ）と `boss_probe_cell(mem, name)` を追加。
  候補は「チャートセル」「1タイル下」「1タイル右」「1タイル左」「1タイル上」
  （1タイル = 8px = チャート64単位）。
- Yジャンプの目標計算（`_want_y_jump` / `_y_jump_step`）はこの関数を使う。
  ボス以外の城・実測セルのない章は従来どおりチャートセル。
- `strategy/orders.py` の `_relaunch_overdue_boss` は、出し直し上限に達したとき
  **未入城かつ次の候補が残っている**場合に限り、候補を1つ進めて出し直し回数をリセットし
  `boss_cell_probe_shift` を記録する。候補を使い切ったら従来どおり `boss_relaunch_exhausted` で保留。
- 章が変わると `boss_cell_probe` は消える（`campaign._enter_chapter` のリセット対象に追加）。

## 検証

- `tests/test_hanjuku_boss_cell_probe.py`（新規6件）: 初期候補はチャートセル／候補番号で1タイル移動／
  通常城は対象外／上限で次の候補へ移り出し直す／候補を使い切ると保留／第3話は単一セルのまま。
- 修正前のコードでは5件失敗、修正後は 6 passed。関連スイート 60 passed。

## 未確認・残件

- 実機で候補セルに入城できるかは未確認。v403 稼働後、`boss_cell_probe_shift` の記録と
  入城メッセージ（`Xしょうぐんがボスじょうにせめこんだ!!`）を突き合わせる。
- 第7〜12章のボスセルと候補は未登録（同じ仕組みを章ごとに足せる）。
- 「軍が出撃しても入城しない」原因がセル以外（行軍日数・経路）だった場合は、
  候補を使い切った時点で `boss_relaunch_exhausted` に戻るので、悪化はしない。
