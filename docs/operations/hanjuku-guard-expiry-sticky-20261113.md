# 半熟英雄: 前線ガードの期限切れを同じ観測内で固定する（v769、2026-11-13）

## 症状（実測 g1163 2026-11-13 15:49）

`ドンドン` の前線ガードが期限切れになった直後、同じ秒に
`front_guard_held` が再記録されました。

```
15:49:25 front_guard_timeout  「前線が1人のまま待ち時間の上限に達したため、単独でも攻撃に出る」
15:49:28 front_guard_held     「前線の城に残る将軍が下限に達するため、この城から攻撃に出さない」
```

`orders()` は1観測で複数回呼ばれます。1回目の `_front_guard_expired()` が
待ち時計を pop して「期限切れ（攻撃可）」を返したあと、次の呼び出しでは
時計が無いため**新しい待ち時計をセットして再びブロック**していました。
1回目が発行した攻撃指示が、実行側のプランから消える原因になります。
`_front_mass_expired()` にも同じ副作用があります。

## 修正（v769 `hanjuku-chart-v769-guard-expiry-sticky`）

- 期限切れになった tick を `front_guard_expired_tick[城]` /
  `front_mass_expired_tick[城]` に記録。
- 同じ tick 内の再呼び出しは**期限切れのまま**（True）を返し、待ち時計を
  再セットしない。
- 次の観測（tick が進む）から再び待てる。

## 検証

- 新規テスト2件（`tests/test_hanjuku_front_mass_wait.py`）
  - 前線ガードの期限切れは同じ観測内で2回呼んでも True
  - 2人待ちの期限切れも同じ観測内で2回呼んでも True
- 第9話 corridor / 派遣 / 城ルート / 前線 / capture guard / probe 関連
  **205件 passed**。
- 修正前の `corridor.py` では新テスト2件が失敗することを確認。

## 本番反映後に実測すること

- `front_guard_timeout` の直後に同じ秒の `front_guard_held` が出ないこと。
- 期限切れ後の攻撃指示が、実行側のプランから消えずに出撃まで進むこと。
- `front_mass_timeout` も同様に再待ちしないこと。

## 残件

- 期限切れを固定するのは観測（tick）単位。同じ tick で状態が変わった場合は
  次の観測まで待つ（入力は1観測1回のため妥当）。
- 第9話の進行と12話ボス撃破は引き続き実測で確認する。
