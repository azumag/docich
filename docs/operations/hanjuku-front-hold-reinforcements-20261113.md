# 半熟英雄: 増援がいる間は前線の最後の1人を出さない（v779、2026-11-13）

## 症状（実測 g1163 2026-11-13 18:5x）

`ドンドン` が1人になった後、v735 の1人待ちの上限（`FRONT_GUARD_WAIT=600`）が
期限切れになり、最後の1人が守備将軍65HPの `オオキク` へ単独出撃して
失われました。城は空になり、`general_location_unknown` が9人に増えました。

```
garrison['ドンドン'] = []                 ← 空
general_location_unknown = [アルテミス, カシュー, ペコリーノ, マフィン,
                            ドリアン, ガスパチョ, サフラン, シェーブル, ヘスティア]
history: オオキク lost 65 / 26 / 65 / 65（単独攻撃の連続）
```

`オシロガ` には4人の増援がいたのに、前線の最後の1人が先に出てしまい、
城を空けて敵に差し出す結果になっていました。

## 原因

1人待ちの上限（v735「前線が1人で固まって進まない」対策）は、**他の城に
増援がいるかどうかを見ていませんでした**。

## 修正（v779 `hanjuku-chart-v779-front-hold-reinforcements`）

- `_reinforcements_known(mem, source)` を追加。自軍の他の城に、主人公以外の
  移動可能な将軍（`garrison` / `garrison_partial` の名前）がいるかを返す。
- 1人待ちの条件を「期限切れ **かつ** 増援が無い」のときだけ解除する。
  - 増援がいる → 前線は最後の1人を出さず、増援の移動を待つ。
  - 増援がいない → 従来どおり期限切れで単独攻撃（v735 の進展ルール）。
- `_finish`（守備将軍がほぼ瀕死）は従来どおり待ちを飛ばす。

## 検証

- 新規 `test_a_front_with_reinforcements_holds_its_last_resident`:
  他の城に2人いれば、期限切れ後も前線の最後の1人は出撃しない。
- 新規 `test_a_front_without_reinforcements_still_marches_after_the_timeout`:
  他の城が空なら、期限切れ後に従来どおり出撃する（v735 を維持）。
- corridor / 前線 / capture guard / 派遣 関連 **181件 passed**。
- 修正前の `corridor.py` では増援ありのテストが失敗することを確認。

## 本番反映後に実測すること

- `オシロガ` に増援がいる間、`ドンドン` の最後の1人が `front_guard_timeout`
  で出撃しないこと。
- 代わりに `オシロガ>ドンドン` の移動が選ばれ、前線が2〜3人になってから
  2人同時の攻撃が出ること。
- 増援が尽きた場合は従来どおり期限切れで攻撃に出ること。

## 残件

- 増援が「移動中」の場合は `_front_names` に現れないため、到着まで待てない
  ことがある。到着後の読み取りで再評価する。
- 第9話の進行と12話ボス撃破は引き続き実測で確認する。
