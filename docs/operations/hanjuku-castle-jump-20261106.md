# 出撃元はXメニューの「しろ」からSELECTで飛ぶ（v462、2026-11-06）

## 指示

オーナー指示（2026-11-06）: 出撃計画で「どの城からどの城へ出撃する」とき、出発地点の城は
Yの全体マップで飛ばず、Xメニューで「しろ」を選び、そこから城の名前を選んでSELECTボタンを押して飛ぶ。
公式マニュアル p.15 も同じ操作を説明している（「自国の城の一覧。Aボタンで各城の状態もチェックできる。
将軍と同じく、セレクトボタンでその城へ飛べるよ。」）。

## 実測した画面（隔離エミュレータ、第1章）

- メインメニュー: ステータス / しょうぐん / しろ / きりふだ / システム / けんのけいこ / セーブ。
  「しろ」にカーソルを合わせると「わがくにの すべてのしろを みることができますぞ!」。
- しろ一覧: 左に島の縮小図、右に自国城の一覧。城名は将軍一覧と同じ x=168、16px 行（y=39, 55, ...）、
  左にオレンジの手、城名の右にレベル。下に
  「Aボタンでステータスひょうじ Bボタンでコマンドにもどりますじゃ!」。
- 一覧でAを押すと城の状態（城名・しゅうにゅう・レベル・しょうぐん数・在城将軍）が開いた。

## 変更

- `flows/map.py`: 出撃元が遠いときの `_want_y_jump(..., 'map')` を廃止し、`castle_jump_step` を追加。
  X→しろ→城名→SELECT の順に操作し、SELECT後にフィールドへ戻ったら屋根検出に依存せずAで城メニューを開く（v466修正）。
  城名は `ー` を除いて照合する（チャートの「アルマムーン」と画面の「アルマームン」）。
  一覧は x=168 の16px行と、A/Bの案内文で識別する。将軍一覧は城名が無いので一致しない。
- `orchestrator.py`: `castle_jump` 実行中は他の画面処理より先にこの手順へ渡す。
- 失敗時は `castle_jump_failed` を記録し、40観測のクールダウン後に再試行する。出撃元をYで飛ぶ経路は残さない。
- 出撃先（マーカー）のYジャンプは従来どおり。

## 未確認・残件

- 隔離プローブでは、一覧でSELECTを送ったつもりが城の状態画面が開いた。Aの押下が残った可能性があり、
  SELECTで飛ぶことは実機で未確認。公式マニュアルとオーナー指示を根拠に実装した。
- 実機で `castle_jump_open` → `castle_jump_confirm` が出て、出撃元の城メニューが開くかを確認する。
  SELECTが状態画面を開く場合は `castle_jump_status` が記録され、1回だけBで戻して再試行し、
  それでも駄目なら `castle_jump_failed` で通常移動へ戻る。
- 城が8つ以上ある章の一覧スクロールは、将軍一覧と同じ16px行を前提にしている。実機の折返しは未確認。

## 実機観測: メインメニューの手カーソル点滅で即失敗（v497、2026-11-07）

g1139 の実機ログ（2026-11-07 00:09–00:15）で、`castle_jump_open` の直後に
`castle_jump_failed`（`why=shiro_missing`, `age=1`）が5回続いた。失敗時の実フレーム
（`hanjuku_frames/frame-105.png`、Xを押した次の観測）を解析すると、メインメニューの行
（ステータス／しょうぐん／しろ／きりふだ／システム）は全て読めていたが、`screen.hand`
が None だった。成功したフレームでは手が `(146, 33, 166, 46)` にある。

拡大比較で、失敗フレームにはオレンジの手が描かれていないこと（行の文字だけが描画済み）を
確認した。手は点滅しており、観測が「隠れている」位相に当たると、メニューが開いていても
`menu_to()` が行を返さない。従来はこれを即 `shiro_missing` として城ジャンプを中止していた。

- `flows/map.py`: 手が読めない観測は即失敗にせず、`CASTLE_JUMP_CURSOR_BLIND`（4観測）まで
  入力なしで再観測する。メインメニューも「しろ」一覧も静止画面なので、保留で状態は変わらない。
  4観測連続で手が読めない場合だけ `hand_hidden` / `list_unreadable` で中止する（従来は一覧のみ3観測）。
- 同じ区間で別の型も観測した（00:24:33 / 23:58:03）: Xの直後1観測だけ画面が `unknown`（メニューへの
  フェード中で文字が読めない）になり、`unexpected_menu` で即中止していた。次の観測ではメインメニューが
  読めている。`CASTLE_JUMP_FADE_BLIND`（2観測）までは同じく保留し、読めないままなら中止する。
- `version.py`: `hanjuku-chart-v497-castle-jump-hand-blink`。

### 検証

- `tests/test_hanjuku_castle_jump.py`: 点滅フレームで保留し、手が戻った次観測で同じ操作を続ける、
  4観測で有界に諦める、しろ一覧でも同様に保留→SELECT、X直後のフェード1観測で保留して次のメニューで
  続行、フェードが続く場合は有界に中止、の5件を追加（計27件）。
- 関連: `test_hanjuku_off_chart.py` / `test_hanjuku_sortie_priority.py` / `test_hanjuku_select_centered.py` /
  `test_hanjuku_y_jump_interrupted.py` / `test_hanjuku_yjump_budget.py` / `test_hanjuku_nav_continuity.py` /
  `test_hanjuku_map_discovery.py` と合わせて222件成功（作業worktree）。
- 実フレーム（g1139 frame-105）を新コードへ通し、`[]`（保留）になり失敗記録が出ないことを確認。

### 残件

- 手の点滅周期そのものは未計測。4観測（約6秒）で足りることはログで確認する。
- 同じ点滅で即失敗する他の `menu_to()` 呼び出し（出撃メニュー等）が残っていないかは未調査。
