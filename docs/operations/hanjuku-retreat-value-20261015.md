# 半熟英雄: 将軍の価値と現在戦力に応じた退却（2026-10-15）

## オーナーの目的

明らかに優勢な戦闘をHP減少だけで放棄しない。強い将軍は早めに保護し、弱い将軍や卵なしはある程度の損失リスクを受け入れて粘る。主人公のゲームオーバー保護、先に使える卵・切り札を確認する方針、現在のゲームと共通配信・音声は維持する。

## コードで確認した問題

既存 `_healthy_melee_advantage` は、現在のHP・兵士込み戦力・将軍の戦闘値が十分に優勢でも、HPが開幕の70%以下になると退却抑止を解除した。例えばゼウスの開幕85→現在55、敵カシュー5、現在兵5対0、資源確認終了の合成条件では、旧 `_hero_retreat_needed` は退却を返す。これは今回ユーザーが見た原画面を特定した再生ではない。

## 判断の順序

新しい判断層 `src/docich/hanjuku/judgment/retreat.py` を、従来名 `_hero_retreat_needed` から呼ぶ。元の関数は `_default_retreat_needed` として残し、特殊・不明条件の保護を変えない。

1. 主人公、敵召喚、ボス、守備戦、攻守未分類、兵数/HP未読、進行中の札、送信済み退却は従来判定を維持する。
2. 現在の通常戦闘パネルを根拠に、HP・兵士込み戦力・戦闘値を掛けた戦力が全て敵の2倍を超えれば、開幕からのHP減少率だけで退却しない。一般将軍のHP12以下は従来保護を残す。ただし資源確認済みの弱い将軍は後述のHP4まで許容する。
3. 使用可能な救済資源の確認終了が確定し、札が不明ではなく、進行中の札計画も未試行の正数卵もない場合だけ、価値別の閾値を適用する。

## 価値の区分と初期閾値

値はゲームのダメージ式・確定勝率ではなく、調整可能な戦略上の初期値。将軍の数値は既存 `hanjuku_reference.general_strength` を使う。

| 区分 | 条件 | 資源確認後の通常白兵での退却 |
| --- | --- | --- |
| 強い将軍 | 戦闘10以上、または最大HP75以上 | 優勢でないHP18以下、または不利かつ最大HPの50%以下。従来の危険判定も保持 |
| 弱い/卵なし | 強い将軍ではなく、戦闘6以下、最大HP40以下、または本人の実観測卵0 | HP4以下、または敵よりHPが少なく開幕HPの20%以下まで粘る |
| 通常/未知 | 上記に該当しない、または数値未確認 | 従来の退却閾値を維持 |

強い将軍は卵0でも「弱い/卵なし」へ降格しない。初期データの卵なし、卵の記録欠落、別人の卵残数は本人の現在の卵0の証明にしない。卵なし将軍も後から卵を取得できるため、観測なしの推測でリスク許容を広げない。

兵数は両軍とも現在の実読0〜6人、HPと戦闘値は本人の既存データと整合する整数だけを使う。保存済みの `retreat_assessment` は毎回作り直し、ホットロード後の許可証として再利用しない。既に送信した退却の確認待ちを新基準で取り消さない。

## 検証と観測

`tests/test_hanjuku_retreat_value.py` は優勢な負傷戦、強い将軍の早期保護、弱い将軍の下限、卵0の根拠、主人公・召喚・守備・未知・資源残存・送信済み操作・保存判断の再評価を検証する。合成パネルのテストであり、自然ランの勝利や死亡回避の証明ではない。

従来の戦闘力テスト3件は「弱い将軍も資源0なら即退却」を前提としていたため、資源確認・0回の保持・非優勢という判定は残し、確認後はリスクを受け入れる期待へ更新する。資源未確認なら従来保護に戻ることも検証する。

既存の退却open/select記録の `observed_metric.retreat_assessment` に区分・理由・有効閾値を追加する。新worker/queue/providerや入力経路は追加しない。実効版は `hanjuku-chart-v223-value-aware-retreat`。
