# 半熟英雄: 6人の名簿を読めても表示が4人に残る（v502、2026-11-07）

## 実測と原因

オーナー報告「将軍数6人なのに4人と誤判定」を、正規read-only
[diagnostics run 42359297075](https://github.com/azumag/docich/actions/runs/42359297075)
と、同active runtimeの固定状態・本番の表示関数の補助読み取りで調べた。
本番のファイル編集・ゲーム入力は実施していない。

g1147、v500、第1章、1年5月の観測:

- `recruit_roster.names` は、どうし・ゼウス・ヴィーナス・ココット・
  アマンディーヌ・リースリングの6人を読み取っていた。`complete=false`。
- `roster_last_complete` は前月（1年4月）の最初の4人を保持していた。
- `roster_pending_joins`、当月の完全な `roster_survey`、国ステータス人数は無い。
- 表示関数 `soviet_now/lib/docich_corner_stats.py::_hanjuku_generals` は
  完全名簿または前月の保存名簿＋追加確認名を使用する。そのため4人になる。

`observed_member` は、当月の完全な状態巡回も保持賃金表もないと、
追加人数を `record_join` に渡す前にreturnしていた。賃金表に全員が載っている
場合の早期returnも、同じように表示用追加記録を省略していた。
これは名簿で6人の名前を認識できない問題とは別の、人数表示への更新漏れ。

## 修正と検証

名前の検証後、状態巡回・賃金表の再利用判定より先に追加確認名を記録する。
同じページの再読は重複加算しない。部分名簿は部分名簿のまま保持し、国の総人数、
個別状態の完全確認、賃金表は新たに確定しない。表示側のコード変更は不要。

- 回帰テスト2件は修正前に失敗、修正後に成功。
- 名簿・状態キャッシュ・予算・月次確認・募集の関連6ファイル:
  315 passed / 1 skipped。
- VMから読み取った実際の表示関数を使い、合成identityと観測と同じ名前構成で
  修正前 `(4, 1-4, base=4, joins=0)` → 修正後 `(6, 1-4, base=4, joins=2)` を確認。
  本番stateの手動更新ではない。
- v502を診断の版allowlistへ追加。worker・queue・registryの契約変更なし。

自己レビュー実施、独立レビュー未実施。本番への反映と実際の配信表示更新は
未確認。PR #3688へ城ジャンプ反復の修正と区別したコミットで追加する。
正規配備後は実判断のv502と表示人数を照合する。
`DOCICH_HANDOFF_PATH` 未設定のため共通正本は未読・未更新で、PRを引き継ぎとする。
