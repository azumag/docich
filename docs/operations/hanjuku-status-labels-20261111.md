# 半熟英雄: 城ステータスの見出し語を将軍として数えない（v678、2026-11-11）

## 症状（実測 22:2x）

`hanjuku_bot.json` のハヤクの在城将軍が次のようになっていました。

```
['ハヤク', 'じょう', 'しゅうにゅう', 'G', 'レベル', 'しょうぐん', 'めい',
 'ラズベリー', 'セルリアク', 'セミヨン']
```

**将軍は3人なのに10人**と記録され、先頭7件は城ステータス画面の見出し語です。
その結果プランナは「この城には予備が10人いる」と信じ、その城から次々に出撃指示を作り、
実際に着くと一覧が空で「出撃元に出せる将軍がいない」として1往復を捨てていました
（実測: 15分で指示13件・出撃8件・`order_done` 6件、16城中5城しか取れていない）。

## 原因

城ステータスの氏名欄読み取り `_names_at(screen, 144, 95, 159)` は、同じ行の
`x=144` の文字列を氏名として拾います。城ステータス画面は見出し語（城名・じょう・
しゅうにゅう・レベル・しょうぐん・めい）を同じ帯に表示するため、これらが氏名として
混入していました。在城人数（`しょうぐんNめい`）と**たまたま件数が一致**したため、
既存の完全性チェックを通過して保存されていました。

## 修正（v678 `hanjuku-chart-v678-status-labels-not-generals`）

`roster.known_generals(names)` を追加し、`fixed_wage(name)` が引ける名前だけを
将軍として残します（将軍名128件の表に無い語＝見出し語）。城ステータスの2か所
（出撃元の在城確認・城の状態確認）で、氏名欄をこの関数に通してから件数照合します。

- 見出し語が混じった読みは件数が合わなくなり「読めない」として棄却され、
  誤った在城者を保存しません（安全側）。
- 実際に3人いて3人読めた場合は、見出し語を除いた3人で件数が一致し保存されます。
- 主人公 `どうし` は賃金表の `しゅじんこう` として残ります。

## 確認

- `tests/test_hanjuku_castle_status_labels.py`（5ケース）: 見出し語の除去／見出し語だけなら
  空／実名は順序維持／主人公を残す／賃金表の全128名が素通りする。
- レジューム・第9話 corridor・層テストをローカル実行（179 passed）。
- 本番反映後: `garrison` に日本語の見出し語が入らないこと、`order_done`
  （出撃元に将軍がいない）の発生率、占領城の増加を実測する。
