# 半熟英雄: 解決しない名簿マーカーを毎将軍で読み直さない（v547、2026-11-09）

## 症状

g1163 第6話 月12-1、2026-11-09 09:58:23〜10:01:55 JST。月次の将軍ステータス巡回で
`post_month_roster_marker_unverified` が**20回**続き、1回あたり**4フレーム**の
再読み取り（`reads: 4`）が発生しました。

観測された `marker_box` はすべて **[59, 120, 64, 125]** ——
同じ静止した赤マーカーで、城候補へ解決できません。

## 原因

`post_month_status` は三角マーカーの読み取りが城候補に解決しないとき、
`MARKER_RETRIES`（4）回まで**同じ将軍でフレームを読み直して**いました
（一時的なスプライト欠け対策）。しかし同じ box が将軍をまたいで繰り返す場合、
それは静止した飾りであり、何回読んでも解決しません。

## 修正（v547 `hanjuku-chart-v547-static-roster-marker`）

- `_static_marker(state, marker)`: 候補に解決しなかった box を state に記憶し、
  次の将軍で**同じ box** が来たら再読み取りせず即「未確認」として個別ステータスへ進む。
- box が変わった場合は従来どおり再読み取りの余地を残す。
- box が城候補に解決したときは記憶を捨てる（次回以降の判断を誤らせない）。

## 確認

- `tests/test_hanjuku_post_month_status.py` に1件追加: 初回は再読み取り可、同じboxは
  即未確認、別boxは再読み取り可、解決したboxは記憶を破棄。
- 月次ステータス・家臣・卵・キャンプ・章スコープ 453件 passed。
- 本番反映後: 月次巡回の `post_month_roster_marker_unverified` の `reads` が1になり、
  巡回時間が短くなることを実測する。
