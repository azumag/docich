# キャンプ放置の4層と砦の帰還 v352（2026-11-01）

Base: `0b9369007`。g1097 第4話で、キッシュ・ヴィーナス・ソーピニヨン・エピィ・ゼウスが全快のままキャンプに残り、ドームが画面に映っていても bot が無入力で待っていた。

## 確認した原因（実フレームと判断ログで実測）

1. **在営の読取が本番で一度も成立していなかった。** `general_status` は y=151 の行を `span(24, 232)` で読み、右の名簿列まで含めて比較していた。実画面の値は `キャンプしています リースリング` になり、`camp_observed` が立たない。#2443 の画面外救出は合成 glyph だけで検証されており、本番では発火しなかった。全将軍の毎月の読取で、場所が `location_observed: False` のまま残っていた。
2. **修理の調査がマップ画面を占有していた。** `house.step` は `map_step` より先に走る。g1097 の保持ログ 137 分で調査を 23 回開始し（19:10 以降の3回の実測で1回約3分）、19:16 / 19:19 / 19:23 に映っていたテントは `camp_found` に届かなかった。保持ログの範囲で `camp_enter` は g839 の 32 回に対し g1097 では 0 回。
3. **一時的な検出途切れが約10分の抑止になり、ドームまで巻き込んでいた。** 19:24:00 の `camp_found` は、歩いてきた将軍がテントに重なって2秒後に見失い、400観測の抑止に入った。テントがドームに変わっても、`kind` 無しの抑止は同じ場所のドームも止めた。
4. **砦のメニューを誰も扱えなかった。** ドームの A は `しゅつげき / こうかん` を開く。分類できないので 19:24 と 19:33 に 101 観測ずつ停止し、`no_input_fallback` で閉じていた。

## 砦の手順（g1097 開始 state の隔離プローブで実測）

- 中の将軍の所在は `キャンプのなかにいます`、砦の持ち主と単独テントは `キャンプしています`、進軍中は `しんぐんちゅうです`。コードが見ていた `いどうしています` は実画面で観測していない。
- ドームで A → `しゅつげき / こうかん`。`しゅつげき` で A → 中の将軍の一覧。名前で A → 本人パネル。次の A → 目的地マーカー（`map_target`）。
- マーカーが砦の上のまま A を押すと出撃は取り消され、砦に残る。B は `map` へ戻る。
- 将軍は城へ送る `しゅつげき` で砦を出る。2人の砦から1人出すと、残る1人は `キャンプしています` になり、絵はテントへ戻る。

## 変更

- 在営の読取を左パネルの `span(24, 168)` に限定し、`キャンプのなかにいます` と `しんぐんちゅうです` を認識する。
- 砦の経路 `fort_menu` → `fort_list` → `fort_status` → `dest` を追加する。目的地は主人公の帰還と同じ Y ジャンプを使う。本人指定があれば一覧でその将軍を選ぶ。
- 調査や修理を始める前に、帰還が動けるキャンプを先に処理する。帰還が抑止中なら調査はそのまま走るので、調査を止め続けない。
- 見失いの再試行は 60 観測から倍増し 400 で頭打ち、砦の次の将軍は 20 観測から同様。どちらも同じキャンプの再失敗で伸びる。テントの抑止はドームへ波及しない。
- 帰還中でない砦のメニューは即座に閉じる。

## 検証と残件

隔離プローブで新コードの実ボットを走らせ、ヴィーナスの砦出撃後に本人の `しんぐんちゅうです`、エピィの `キャンプしています`、絵のテント化を実画面で確認した。名簿→SELECT→砦→本人指定の経路も同じ state で通した。プローブは送信記録を持たないため `dispatch_unconfirmed` で終わる。本番の `input_sent` と到着は配備後に確認する。

- ゼウスはあたしの家の隣の砦で卵が壊れたまま残っていた。帰還後の再派遣は既存の修理経路に任せる。家で修理が成立しなかった理由は未調査。
- 修理の調査が1か月に最大4回走る量そのものは変えていない（g1097 の 23 回を1回約3分とすると約70分）。
