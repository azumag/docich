# 半熟英雄: 守備将軍の現在HPパネルを過去の戦闘履歴より優先する（v787、2026-11-13）

## 症状（実測 g1163 2026-11-13 21:0x）

`オオキク` への攻撃で守備将軍を **3 HP** まで削りました（143786 lost 3）。
ところが次の攻撃（143840、54 tick 後）は守備将軍 **60 HP** と戦って敗れました。

```
143786 オオキク lost enemy_hp=3
143840 オオキク lost enemy_hp=60   ← 守備将軍が回復/交代していた
```

`_defender_nearly_dead` は「直前の戦闘で3HPまで削った」履歴を「止め」と
みなし、回復後の高い守備将軍にも止め攻撃を出していました。

## 原因

`_defender_nearly_dead` はパネルHPが `FINISHING_HP` 以下のときだけ真とし、
**高いパネルHPのときは過去の `sortie_history` にフォールバック**していました。
守備将軍が回復・交代していても、古い3HPの履歴が残っていれば止め扱いです。

## 修正（v787 `hanjuku-chart-v787-panel-finish-precedence`）

- 現在のパネルHP（`castle_defenders[target].hp`）が正の整数なら、それを
  唯一の根拠にする: `panel_hp <= FINISHING_HP` のときだけ止め。
- `sortie_history` へのフォールバックは、パネルHPが無い/0のときだけ。

守備将軍が回復・交代した場合は止め扱いにならず、2人待ち・増援の判断に戻ります。

## 検証

- 新規 `test_a_current_high_panel_beats_a_stale_three_hp_history`:
  パネル60HP + 履歴3HP では止めにしない。
- 既存の「24HPの履歴で止め」「パネル3HPで止め」テストはそのまま passed。
- corridor / 前線 / capture guard / 派遣 関連 **183件 passed**。
- 修正前の `corridor.py` では新テストが失敗することを確認。

## 本番反映後に実測すること

- 守備将軍が回復・交代した後、古い低HP履歴で止め攻撃を出さないこと。
- 現在のパネルが低HPのときは従来どおり止めで攻撃に出ること。
- 止め攻撃の無駄な損失が減ること。

## 残件

- パネルHPは戦闘パネル読みに依存する。読めない場合は履歴フォールバックのまま。
- 第9話の進行と12話ボス撃破は引き続き実測で確認する。
