# 半熟英雄: 計画が差し替わっても指示IDを再利用しない（v789、2026-11-13）

## 症状（実測 g1163 2026-11-13 21:37/21:40）

同じ指示ID `I:c9:ハヤク>タオ:45` の `order_done`
（「出撃元に出せる将軍がいないため、この城を一時的に対象から外す」）が
3分おきに2回記録されました。

```
21:37:50 order_done I:c9:ハヤク>タオ:45
21:40:36 order_done I:c9:ハヤク>タオ:45
```

## 原因

`corridor._step` は**現在の計画の `orders`** だけから使用済みIDを数えて
いました。計画が差し替わると（`chart_adjust_applied` や新月）、終了済みの
IDを忘れ、同じIDを再発行して空の出撃元の指示を再実行していました。

## 修正（v789 `hanjuku-chart-v789-step-id-collision`）

`_step` の使用済みIDに、`world.launched_orders` と `sorties` の
同じ城ペアのIDも加えます。計画が差し替わっても、出撃済み・終了済みの
IDは再利用されません。

## 検証

- 新規 `test_a_step_id_does_not_collide_after_the_plan_is_replaced`:
  計画の orders が空でも launched_orders に45があれば次は46。
- corridor / 前線 / 派遣 関連 **189件 passed**。
- 修正前の `corridor.py` では新テストが失敗することを確認。

## 本番反映後に実測すること

- 計画差し替え後に同じ指示IDが再実行されないこと。
- 空の出撃元（ハヤク/アルマムーン）の `order_done` が繰り返されないこと。
- 指示IDの衝突による「出せる将軍がいない」サイクルが減ること。

## 残件

- IDは城ペアごとの連番。差し替えを跨いだ履歴を保持する。
- 第9話の進行と12話ボス撃破は引き続き実測で確認する。
