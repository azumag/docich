# 半熟英雄: 所在不明の印を期限付きにし、軍が丸ごと出撃不能になるのを防ぐ（v680、2026-11-11）

## 症状（実測 23:0x）

| 項目 | 値 |
|---|---|
| 名簿の生存将軍 | **32** |
| `general_location_unknown` | **36**（うち生存29） |
| 城に居ると分かっている将軍 | **1**（＋主人公など2） |
| 出撃に使える将軍 | **実質3人** |

行軍が到着期限を超えると、その将軍は「所在不明」として以後の出撃から除外されます。
ところが第9話の機械進軍では道中の城の一覧を読み直す経路が無く、**印は増える一方**でした
（`sortie_location_recheck_queued` が1時間に7件）。結果、32人中29人が締め出され、
前線へ届く将軍が枯れて占領城が3↔5を往復していました。

## 原因

`_queue_overdue_location_recheck` は「期限超過は到着の証拠ではない」として正しく印を付けますが、
印を消すのは「その城の実一覧で本人を確認したとき」だけです。第9話では前線の城が空で
一覧を読む機会が無いため、消える機会が訪れませんでした。

## 修正（v680 `hanjuku-chart-v680-location-unknown-ttl`）

印に時刻を持たせ、**期限（`LOCATION_UNKNOWN_TTL` = 800 tick＝約13分）を過ぎたら解放**します。

- `mark_location_unknown(mem, name)`（`os_layer/world.py`）: 印と同時に最初の時刻を記録。
- `expire_unknown_locations(mem)`: 期限切れの印だけを外す。時刻の無い印はその場で時計を
  開始し、いきなり解放はしません（記録直後に消えるのを防ぐ）。
- 呼び出しは第9話の機械進軍 `corridor.orders()` の先頭。出撃すれば実一覧を読むので、
  そこでの観測（`garrison_seen`／`deploy` の在城者更新）が正式に印を消します。

期限切れで出した将軍が実際には別の城にいても、出撃元の一覧に居なければ従来どおり
「出せる将軍がいない」で指示が閉じるだけで、危険な操作は増えません。

## 確認

- `tests/test_hanjuku_location_unknown_ttl.py`（7ケース）: 新しい印は保持／期限切れだけ解放／
  一部だけ期限切れ／時刻なしは時計開始のみ／印は最初の時刻を保持／空名は無視／空一覧は無変化。
- 第9話 corridor・機械進軍・層テストをローカル実行（74 passed）。
- 本番反映後: `general_location_unknown` の件数が減少し、1時間あたりの出撃数と占領城が
  増えることを実測する。
