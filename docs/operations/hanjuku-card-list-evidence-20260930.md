# 札一覧の描画途中と携行不足を区別する

g490のゼウスはナキューメラ出撃時にイッテツーン2枚を選択し、出撃確認で同じ2枚を読めた。戦闘では一覧のOCRが空の1観測だけでbattle_card_missingとなり、札を使わず召喚して勝利した。所持札が実際に消えたか、描画途中だったかは未確定。保存画像はリング上書きでSHAが一致しなかったため当該時刻の証拠として使用しない。

v90では対象札が読めれば従来通り直ちに選ぶ。「きりふだはありません」「きりふだなし」は明示的な不足として直ちに閉じる。対象札のない読める一覧は同じ札名列の2連続観測で不足を判定する。空・変動する一覧は最大4観測で閉じ、battle_card_list_unclassifiedを記録する。未分類の一覧からcards_missingや消費を推定しない。退却・救済・チャートの使用条件と札順を維持する。追加待機を札が存在する通常連携へ入れない。

描画途中→対象札の出現、変動する札名列、持続する未読一覧、明示的な空一覧、安定した別札一覧の回帰を確認する。独立レビューは未実施（このタスクではサブエージェント禁止）、自己レビューとCIを区別する。実ゲームでの札選択、ボス勝利・章進行・ゲームクリアは別途監視する。

既存bot commandのホットロード対象のみ。worker/model/provider/queue設定は変更せず、追加の固定構造イベントは既存battle_card系列と同じcontext/snapshot収集を使用する。対象旧ファイルを退避し、PR・最新CI・protected main・canonical Actions配備後に対象SHAと同一ゲームでの実action_plan版切替を照合する。
