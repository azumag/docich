# 札一覧の描画途中と携行不足を区別する

g490のゼウスはナキューメラ出撃時にイッテツーン2枚を選択し、出撃確認で同じ2枚を読めた。戦闘では一覧のOCRが空の1観測だけでbattle_card_missingとなり、札を使わず召喚して勝利した。所持札が実際に消えたか、描画途中だったかは未確定。保存frame-049.pngをFrame.resized().digest()（RGB画素SHA）で照合し、ログの4b87ef1360e9b832a69e20efd11e30eab051115b7ebc9d572c871a15240d8d89と一致した。画面は札名の無い「ほ」だけ描画された台詞。PNGバイトSHAとRGB画素SHAの比較は誤りで、途中の上書き推定を訂正する。

v90では対象札が読めれば従来通り直ちに選ぶ。「きりふだはありません」「きりふだなし」は明示的な不足として直ちに閉じる。対象札のない読める一覧は同じ札名列の2連続観測で不足を判定する。空・変動する一覧は最大4観測で閉じ、battle_card_list_unclassifiedを記録する。未分類の一覧からcards_missingや消費を推定しない。退却・救済・チャートの使用条件と札順を維持する。追加待機を札が存在する通常連携へ入れない。

描画途中→対象札の出現、変動する札名列、持続する未読一覧、明示的な空一覧、安定した別札一覧の回帰を確認する。独立レビューは未実施（このタスクではサブエージェント禁止）、自己レビューとCIを区別する。実ゲームでの札選択、ボス勝利・章進行・ゲームクリアは別途監視する。

既存bot commandのホットロード対象のみ。worker/model/provider/queue設定は変更せず、追加の固定構造イベントは既存battle_card系列と同じcontext/snapshot収集を使用する。対象旧ファイルを退避し、PR・最新CI・protected main・canonical Actions配備後に対象SHAと同一ゲームでの実action_plan版切替を照合する。

同じg490の第1話8月の月次おねだり「だからなんかかって。」と3価格を商人一覧へ誤分類し、Bを繰り返した。固定文字署名を価格一覧より先にgift_requestへ判定し、商品抽出を右側144px以降のspansへ限定して左の同一行台詞を商品名へ混ぜない。現物RGB SHA3bd1851567012f181b5622298a3222b81bc90e7229cc2a09c6f7132839848c35を再生し、gift_requestと最安ピアス50GのA選択を確認する。所持金30Gで価格50Gは未購入。復旧は既存owner補助SSH経由のcanonical docich send（active照合/入力フェンス）でAを1回送信し、次のゼウス防衛戦に進んだことを確認。最初の入力ゲート取得タイムアウトは未送信で、同一経路を1回再試行した。ゲーム/共通配信再起動・tracked files直接編集なし。
