# 半熟英雄: 前線に増援が着いたら2人待ちの時計をリセットする（v776、2026-11-13）

## 症状（実測 g1163 2026-11-13 17:5x）

`ドンドン` に2人しかいない前線へ `オシロガ` から4人が向かっていましたが、
2人待ちの上限（`FRONT_MASS_WAIT=900`）が**増援の到着を待たずに**期限切れに
なり、1人だけで守備将軍71HPの `オオキク` へ攻撃して失いました。

```
17:5x ドンドン 2人（ペコリーノ/アルテミス）、オシロガ 4人が移動中
       front_mass_timeout → 単独攻撃 → オオキク lost enemy_hp=71
```

## 原因

`_front_mass_expired` は待ち始めの tick だけを保持し、**前線の人数が増えても
時計をリセットしていませんでした**。増援が歩いている間に上限が来ると、
集まる前に単独攻撃を始めてしまいます。

## 修正（v776 `hanjuku-chart-v776-mass-hold-reset`）

- `_front_mass_expired(mem, castle, count=None)` が前線の人数
  （`front_mass_count`）を記録。
- 人数が前回と変わったら待ち時計と期限切れ固定をリセットし、新しい人数で
  待ち直す。
- 単独攻撃は「前線の人数が変わらないまま900 tick 経過した」ときだけ。
- 呼び出し側は現在の在城者数 `len(_front_names_now)` を渡す。

## 検証

- 新規テスト2件（`tests/test_hanjuku_front_mass_wait.py`）
  - 人数が増えたら待ち時計がリセットされ、期限切れにならない
  - 人数が変わらなければ従来どおり期限切れになる
- 第9話 corridor / 派遣 / 城ルート / 前線 / capture guard 関連
  **178件 passed**。
- 修正前の `corridor.py` では新テスト2件が失敗することを確認。

## 本番反映後に実測すること

- 増援が前線に着くと `front_mass_timeout` が出ず、人数が集まるまで待つこと。
- 集まった後に2人同時で攻撃し、単独攻撃の損失が減ること。
- 増援が来ない場合は900 tick で従来どおり単独攻撃に出ること。

## 残件

- 人数の変化は `_front_names_now`（完全読み/ページ）に依存する。ページが
  古い場合は v766 の tick 比較で新しい方を採る。
- 第9話の進行と12話ボス撃破は引き続き実測で確認する。
