# 半熟英雄: 将軍が動いたらその城のページ下限を捨てる（v777、2026-11-13）

## 症状（実測 g1163 2026-11-13 17:5x）

`ドンドン` には2人（ペコリーノ / アルテミス）しかいませんでしたが、
`garrison_partial` には4人
（ジェラート / ラビオリ / クランベリー / ペコリーノ）が残っていました。
`_front_names` は v766 の tick 比較で新しい方を採りますが、ページが
「移動前のスナップショット」であるため、将軍が出た後も4人のままでした。

その結果、2人同時出撃の待ち条件（`_keep + 2 = 3`）を満たしたと誤認し、
1人で守備将軍71HPの `オオキク` へ攻撃して失いました。

## 原因

`_garrison_move`（将軍の移動・入城）は完全な `garrison` を更新しますが、
`garrison_partial` / `garrison_partial_tick` を残していました。ページは
移動前の在城者のスナップショットなので、移動後は人数が変わっています。

## 修正（v777 `hanjuku-chart-v777-partial-on-move`）

`_garrison_move` が、移動元 `source` と移動先 `target` の
`garrison_partial` と `garrison_partial_tick` を削除します。

- 以後の人数判断は更新済みの完全リスト（または新しいページ）を使う。
- ページ自体は次の一覧読みで新しく入る。

## 検証

- 新規 `test_a_move_clears_the_page_for_both_castles`:
  移動元・移動先のページが消え、完全リストが更新される。
- corridor / 前線 / capture guard / 派遣 関連 **166件 passed**。
- 修正前の `orders.py` では新テストが失敗することを確認。

## 本番反映後に実測すること

- 将軍の移動後に `garrison_partial` の該当城が消えること。
- 前線の人数が実際の在城者数（完全リスト）で判断され、
  2人待ちが正しく働くこと。
- 単独攻撃で守備将軍を育てる損失が減ること。

## 残件

- ページの読み直しは次の一覧読みに依存する。読まれない間は完全リストの
  人数で判断する（古い完全リストの可能性は v766 の tick 比較で扱う）。
- 第9話の進行と12話ボス撃破は引き続き実測で確認する。
