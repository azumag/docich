# 半熟英雄: 不足したボス札を商人で買い直す

v235（`hanjuku-chart-v235-boss-card-rebuy`）。関連: #2374（在庫切れが証明できたボス札を外して出撃を続ける、v233）、#2368（兵士20人以下の月は補充を最優先、v232）。

## 背景（g825、2026-10-17）

runtime `g825-0111756c`（終了理由 `input_stalled`）の判断ログで、第1話ボス注文 1-B1（クースカン＋ノリウツール）の札選択画面が 08:58〜09:39 JST に保留を続けた（`situation_held` 412回、理由「予定切り札の正数在庫と携行余枠を確認できないため選択せず保留」、対象 card=クースカン）。

- 第1話のチャート上の購入は1年5月の1回だけ（クースカン4枚を含む）。それ以降の月計画には切り札の補充が無い（ログは 07:30 からのため、1年5月の実購入は未照合）。
- 非ボスの出撃で、強い切り札の追加携行（`strong_card_kit`）がクースカンを10回選んだ（07:52〜09:10）。1-11 の調整計画と 2-2 の特売で1枚ずつ買い足した分も、07:52・08:12・08:28 の非ボス出撃で持ち出された。
- 2-8（127G、兵14人）は募集50G・兵士29人・築城14G、2-9（88G、兵43人）は募集50Gに使われ、クースカン（24G）は買われなかった。2-8 の特売計画（`bargain_plan`）はノリウツール1枚だけでクースカンを含まず、そのノリウツールも予約資金の照合で見送られた（`buy_skip` `reserved_funds`）。
- 札一覧は ID 順で表示されるが、4行の窓に出ない札は `card_stock` が更新されず、クースカンは在庫1のまま残った。08:38 以降は一覧に無いクースカンを強い札として選んでは外す（`card_dropped`）ことを繰り返した。

## 判断

### 不足の判定（`strategy/boss_cards.py`）

- 対象は現在の章の基礎チャートのボス注文（`_strict_boss_cards` と同じ注文）で、注文が未出撃（`None`/`pending`）の間だけ。出撃中（`launched`/`launched_unconfirmed`）・再試行上限（`failed`）・撃破済み・イベント札キットへの置換後は対象外。
- 札ごとの必要枚数と、`card_stock`（札一覧で実測した在庫）＋未確認の購入（`card_bought_unseen`）＋当月の計画済み購入を比べる。**実測が無い札は不足の証拠にしない。**
- 札一覧の観測で、表示行の ID の間に入る札は在庫0と記録する（#2374 の `_card_proven_absent` と同じ証明）。4行未満の一覧の扱いは従来どおり。ボス出撃で在庫切れが証明された札は、一覧に一度も出ていなくても在庫0と記録する。

### 予算と順序

- 新しい月の計画（`_plan_extras`）で、卵回復の予約と家の修理費を設定した後、募集費と兵士の予算を決める前に計画する。不足札を商人の購入リストの先頭に入れる。
- 使える額は `_merchant_spendable`（賃金予備・卵回復の予約・修理費・募集予約を残した所持金）。足りない分は買わず `boss_card_rebuy_deferred`（`insufficient_funds`）を記録し、翌月に再判定する。
- 兵士の予定人数と募集費の予約は、ボス札の代金を引いた残りから決める（チャートの切り札と同じ扱い）。
- この章の後の月に基礎チャートの購入がある間は買わない（`chart_purchase_ahead`。特売の買い足しと同じ扱い）。
- **兵士20人以下の月とは衝突しない。** `_low_army_refill` と `_soldier_spendable` は未購入の札を差し引かず、補充の支払いを確認するまで商人を開かない。買い直しは補充後の残金から、他の購入と同じ照合で行う。

### 買い直した札の扱い

- 商人の見積を照合して購入を確定した時（`bought` と同じ根拠）に、ボス注文の `card_drop` から購入枚数分を戻す。同じ注文の札送り回数（`card_scroll`）と札の見失い回数（`card_miss`）も戻し、次のボス出撃で札を探し直す。実在しなければ #2374 の証明で再び外れる。
- 購入枚数は `card_bought_unseen` に記録し、次の札一覧でその札を読むまで重ねて買わない。`card_stock` は購入では変えない（観測だけを記録する）。

### 強い切り札の追加携行

- オーナー方針（2026-10-03）の強い切り札の追加携行は維持する。ただし非ボスの出撃では、ボス注文が必要とする枚数以下しか在庫が無い札は足さない（`strong_card_reserved_for_boss`、月・注文ごとに1回記録）。必要数を超える余剰、ボス出撃そのもの、ボス撃破後は従来どおり足す。

## 判断ログ

| decision | 内容 |
|---|---|
| `boss_card_rebuy_plan` | 計画した札・枚数、不足数、実測在庫、未確認購入、外した札、使える額 |
| `boss_card_rebuy_deferred` | `insufficient_funds` または `chart_purchase_ahead` と同じ根拠 |
| `boss_card_restored` / `boss_card_bought` | 購入確定後に外した札から戻した枚数（戻す札が無ければ `boss_card_bought`） |
| `strong_card_reserved_for_boss` | 非ボス出撃で強い札として足さなかった札と在庫 |

## 反映と確認

PRのテスト・CI確認後にmainへ統合し、既存のVM operationsから正規配布する。戦略は観測ごとのBotサブプロセスで読み込むため、配信全体やゲームを再起動しない。

CI成功、VMへの配布、実プレイでの成立はそれぞれ別に確認する。実プレイでは同じ run の判断ログで、ボス札の在庫0（`card_stock` 0 または `card_dropped`）→ 翌月の `boss_card_rebuy_plan` → `buy` → `boss_card_restored` → ボス出撃の `card_pick`（その札）の順になることを確認する。
