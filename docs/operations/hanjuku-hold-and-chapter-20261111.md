# 半熟英雄: 読めない画面で止まる／章が決まらない停滞を減らす（v673、2026-11-11）

## 1. 2コマ点滅の読めない画面で入力が止まり、画面停滞でコーナーが終了していた

### 症状（実測 19:09:57–19:15:04）

`phase=event` の読めない画面が **2つのフレーム（`f9156110` と `37c1b390`）を交互に点滅** させたまま
5分間止まりました。この間 `observation` は **186件**、`input_sent` は **0件**。
`unchanged_seconds` が 301 秒に達して `screen_stalled` がラッチし、**19:15:04 から 19:37:09 まで
観測そのものが止まりました**（`hanjuku_run.observe` は終端ラッチ中は何も書かずに戻るため）。
復帰はオペレータの `docich hanjuku-clear-terminal`（19:37:09）だけで、22分間まるごと失われました。

### 原因

`orchestrator.unknown_hold_advance` は「同じ画面が6回続いたらAを1回送る」有界の脱出ですが、
同一判定を **直前1コマの digest** とだけ比較していました。点滅画面は毎回 digest が変わるため
`n` が毎回1に戻り、**上限に一度も到達せずAが送られません**。

`hanjuku_run.observe` 側は同じ点滅を「直近2つの digest を含む画面」として1つの無変化画面と
みなしており（`recent_frame_sha256`）、判定が食い違っていました。

### 修正

`unknown_hold_watch` に直近2つの digest を保持し、**そのどちらかと同じなら同じ画面**と数えます。
3コマ以上の周期で変わる画面は従来どおり別画面として数えるため、反応している画面では押しません。

## 2. 城名だけが出る画面から章が確定しない

### 症状

`resume_chapter_pending`（または `chapter` 未確定）のまま章が確定せず、`chapter: None` のため
チャートが使えず攻略（出撃計画）が始まらない状態が続きました。

### 原因

章の確定は `CASTLE_STATUS` 正規表現（「<城> … LvN しょうぐん」の完全な行）に依存しており、
**城メニューのように城名だけが出る画面**では一致せず `observe_chapter_castle` が呼ばれませんでした。

### 修正

章が未確定のあいだは、画面テキストに**既知の城名がそのまま1行で含まれていれば**
`observe_chapter_castle` を呼びます。

- 章の確定条件は従来どおり「その城名が1つの章にしか存在しない」場合のみ（判定側は不変）。
- 1画面に複数の城名が出るときは曖昧なので確定しません（先頭を選ばない）。
- 部分一致（前後に文字が付いた行）は根拠にしません。
- 章が確定済みなら動かないため、ステータス画面が進行中の章を書き換えません。

## 確認

- `tests/test_hanjuku_unknown_hold.py`: 2コマ点滅で有界Aが1回だけ出る／3コマ周期では出ない、
  既存の「変化する画面では押さない」「戦闘中は連続コマ数で押す」を維持。
- `tests/test_hanjuku_chapter_name_fallback.py`: 単一・複数・部分一致・重複・保留なし・章なし実行中の6ケース。
- 半熟の関連テストをCIで実行。
- 本番反映後: `unknown_hold_advance` が点滅画面で記録され、`screen_stalled` のラッチが
  発生しないこと、城メニューから章が確定することを実測する。
