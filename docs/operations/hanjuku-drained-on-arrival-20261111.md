# 半熟英雄: 中継城は「到着した将軍」でだけ補充する（v677、2026-11-11）

## 症状（実測 20:3x–21:4x）

第9話の指示 93 件のうち、開始後の結末は次のとおりでした。

| 結末 | 件数 |
|---|---|
| `order_launched`（出撃成功） | 22 |
| `sortie_held_target_reserved`（重複奪還で取り消し） | 50 |
| `order_done`／「出撃元に出せる将軍がいない」 | 21 |
| `source_not_under_cursor` | 4 |
| その他 | 8 |

`sortie_held_target_reserved` は別PR（#3946）で解消し、直近20分は
`order_start` 10・出撃 8・取り消し 0 まで改善しました。残る無駄が
**「出撃元に将軍がいない」21件**です。

## 原因

`corridor._drained()` は、空だった城に**将軍を送っただけ**（まだ行軍中）で
「空でない」と判断し、その城からの出撃指示を作っていました。出撃元に着くと
一覧は空なので「出せる将軍がいない」で指示を閉じ、1往復ぶんの操作を捨てます。

## 修正（v677 `hanjuku-chart-v677-drained-on-arrival`）

中継城の補充は**到着が確認できた将軍**だけを根拠にします。

- `status == 'arrived'`（行先の実一覧で本人を確認、または移動完了を観測）で解除。
- 行軍の到着窓を過ぎた（`ARRIVAL_RECHECK_TICKS` = 120 tick）場合は居場所不明なので、
  一度だけ実一覧を読み直して再判定します（取りこぼしで前線が渇くのを防ぐ）。
- 月が変わったら従来どおり解除。

## 確認

- `tests/test_hanjuku_corridor_drained.py`（7ケース）: 行軍中は補充しない／到着で解除／
  到着窓を過ぎたら再確認／空読みより前の便は根拠にしない／月替わりで解除／
  主人公だけの城は移動目的なら前進を止めない。
- 第9話 corridor の関連テストと層テストをローカル実行（62 passed）。
- 本番反映後: `order_done`（出撃元に将軍がいない）の発生率と、1時間あたりの出撃数を実測する。
