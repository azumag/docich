# 半熟英雄の一覧・数量入力のローカル校正（2026-11-15）

## 環境と再現方法

既存のローカルROM `games/roms/hanjuku-hero.sfc` と隔離環境の保存状態を、
Snes9x libretro 1.63 (`fae2fea`) へロードした。ROM・保存状態・コアはGitに追加しない。
コアのSHA-256は `8ed333ac04544cc6ab67ceb445d095f7600bb17586d4887d99117fbd1ef776f6`。
本番のゲーム・配信プロセスや保存状態には入力・書き込みを行っていない。

既存のローカル `tmp/hanjuku-local/core_driver.py` のCoreと画像コールバックを使用し、
bot runner・autosave・runtime更新は呼ばず、メモリ上のコアだけを操作した。
各比較は同じ保存状態を再ロードし、方向キーを6フレーム押して解放し、無入力で再観測した。
一覧の連続入力は6フレーム押下・3フレーム解放を4回とした（100ms/50ms相当）。
画面を取り直し、実カーソルと文字列で移動結果を確認した。
メニューを最初に開いた直後は初回の方向入力が移動にならない場合も観測したため、
送信したキーの回数を到達証拠にはしない。

## 実測

|画面・操作|同じ状態からの結果|採用範囲|
|---|---|---|
|将軍一覧、Down 4回（各100ms、解放50ms）|どうし（y39）からバトウラ（y103）へ4行移動|全経路が読める目標への最大4入力|
|将軍一覧先頭、Up|先頭のまま|末尾への折返しは利用しない|
|将軍一覧、Left/Right/L/Rを各1回|名前・カーソル・表示ページの変化なし|ページ送りは追加しない|
|将軍詳細、Up/Down/Left/Right/L/Rを各1回|どうしの詳細表示のまま|次の将軍への直接切替は追加しない|
|商人数量1個、一の位、Up/Down 100ms|2個/0個へ変化|既存の単発入力後の再観測だけを早める|
|商人数量1個、一の位、Left 100ms|十の位へ移動、数量1個のまま|同上|
|商人数量、L/R 100ms|数量・桁の変化なし|肩ボタンの短縮操作は追加しない|
|商人数量1個、Up長押し|6〜30frは2個、45frは3個、60frは5個|一定回数の変化を保証できないため長押し短縮は追加しない|

上記の無変化は、この保存状態と入力条件での観測である。全画面・全コアでショートカットが
存在しないという証明ではない。城一覧・先発隊・卵回復・砦での連続入力の受付は今回の
エミュレータ測定対象外であり、保存画像と合成画面による経路判定テストと区別する。

商人の数量画面を未加工のPNGで保存したものは以下の回帰fixtureである。

- `tests/fixtures/hanjuku/local-merchant-quantity-ones.png`: 1個、一の位。
- `tests/fixtures/hanjuku/local-merchant-quantity-tens.png`: Left後の1個、十の位。
- `tests/fixtures/hanjuku/local-merchant-quantity-two.png`: Up後の2個、一の位。

## 実装の境界

卵回復・砦・部分的な将軍再確認・先発隊の上段について、現カーソルから目標までの
全行が一意に読める場合だけ連続入力する。卵回復の全回復y47と最初の将軍y71の間隔は
通常の16px行と異なるため、明示した行順で数える。先発隊は既存の3入力/バーストと
9入力上限を、連続入力中の実入力数で消費する。選択済みで暗転した上段の行や欠落行を
経路として使わない。全名簿の巡回、未表示の名前の探索は従来の1行ずつの観測を維持する。

商人はy183の数量・合計金額の固定文とy199の問い、桁と手カーソルが同じ画面で読める場合だけ、
単発100msの上下・有効な桁移動の再観測周期を1500msから500msにする。
この読みは数量・価格・購入完了の新しい証拠を作らず、購入判断や支払い照合には使用しない。
A/B、長押し、複数入力、未読・曖昧な画面は通常周期を維持する。

実ゲーム全体の時間短縮率と本番への反映・効果は未測定。
