# 半熟英雄: 城一覧の巡回予算が同じ名簿の再読で毎回復活し、30分に27回巡回していた（v758、2026-11-13）

## 症状（実測 g1163 2026-11-13 11:15〜11:45）

30分の decision ログ 1391 件のうち `roster_probe` が **27件**。巡回は
`アルマムーン` / `タオ` / `ハヤク` など既に空と分かっている城へ繰り返し入り、
`order_done`（出撃元に将軍がいない）で閉じていました。

同じ時間帯の `country_general_count` は 29（当月スコープ）、在城は
`オシロガ` / `ドンドン` の数名のみ。巡回しても野営中の将軍は城一覧に出ないため、
27回の訪問はほぼ時間の浪費でした。

## 原因

`_probe_budget_left()` は「城一覧に将軍が現れたら予算を復活」を
**在城者の合計人数**（`_garrison_seen()` の合計）と前回値の比較で判定していました。

```python
if _garrison_seen(mem) > int(state.get('seen') or 0):
    return True
```

第9話では出撃のたびに `オシロガ` / `ドンドン` の一覧を読み、ページによって
見える人数が増減します。合計が前回より1人でも増えると予算が復活するため、
月6回の上限が実質無制限になっていました。既に空の城を何度も読み直すだけで、
新しい将軍の所在は見つかりません。

## 修正（v758 `hanjuku-chart-v758-probe-rearm-names`）

予算の復活判定を**人数**から**名前の集合**へ変えました。

- `_garrison_names()` を追加し、`world.garrison` に現れた将軍名の集合を取る。
- `corridor_probe.seen_names` に前回の集合を保存する。
- 復活するのは「前回までに無い名前が城一覧に現れたとき」だけ
  （帰還・入城・募集加入など、本当に新しい所在の手がかり）。
- 同じ名簿を何度読んでも予算は復活しない。`PROBE_REARM_TICKS=3600` の
  時間による復活は従来どおり。

## 検証

- `tests/test_hanjuku_corridor_probe_budget.py`
  - 同じ名前の再読では `roster_probe` が増えない。
  - 新しい名前（キャロット）が一覧に現れたら予算が復活する。
- 既存の第9話 corridor / 派遣 / 城ルート / 前線 / capture guard 関連
  **146 件 passed**。
- 修正前の `corridor.py` では新テスト2件が失敗することを確認。

## 本番反映後に実測すること

- 30分あたりの `roster_probe` が27件から月6回＋新しい名前の分へ減ること。
- 巡回に使っていた時間が移動・出撃へ回り、`order_start` / `order_launched` が
  増えること。
- 新しい将軍が城一覧に現れたときは巡回が復活すること。

## 残件

- 野営中の将軍は城一覧に出ないため、この巡回では見つからない（#3963 / #3978）。
- 第9話の進行と12話ボス撃破は引き続き実測で確認する。
