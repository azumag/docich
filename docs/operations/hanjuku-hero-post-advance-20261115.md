# 半熟英雄: 第9話で主人公の城が前線に追随しない（v844、2026-11-15）

## 症状（オーナー報告 2026-11-15）

> ９話では、一つ敵城を落としたら前線を一つあげられるので、主人公のいる城も
> ひとつ上げられるはずだが、それが今動いていない

第9話の機械進軍は v684 から「主人公を前線の一つ後ろの自城に常駐させ、前線が
一城進むごとに主人公も一城進める」規則を持つ（`corridor._hero_post_order`）。
ところが実ラン `g1163` の状態では、所有5城のどの在城記録にも主人公がおらず、
`corridor.orders()` は主人公の指示を一度も発行していなかった。

再現（ローカルに取得した実 state のコピー、第9話 tick 175799）:

```
owned        = ['アルマムーン', 'オシロガ', 'サヌト', 'タオ', 'ハヤク']
_hero_castle = None
orders       = [I:c9:オシロガ>ドンドン:164 (retake)]   # 主人公の指示なし
```

## 原因

- 主人公の移動は出撃として実行されるため、出発時に出撃元の在城記録から本人が
  消え、到着は「到着先の城一覧を読んだとき」にしか記録されない
  （`_garrison_move` は source だけを消す）。
- 到着先の一覧は、その城への未読の移動がある間だけ巡回（`routes.probe_due`）で
  読まれる。巡回予算が尽きる、または城が drained 扱いで訪問対象から外れると、
  一覧は二度と読まれない。
- `_hero_post_order` は `_hero_castle(mem)` が返す城からしか動かせないため、
  所在が記録から消えた時点で、前線が何城進んでも主人公の指示は出なくなる。
- 第9話の月次処理はボス段階前は修理だけで、将軍ステータス走査（v826 の
  主人公位置）も走らない。城一覧以外に所在を束縛する経路が無い。

## 修正（v844 `hanjuku-chart-v844-hero-post-advance`）

1. **出発の記録（`hero_post`）**: 主人公の corridor 移動が出発確定した時点で、
   行き先を「主人公のいる城」の推定として記録する（`map._commit_departure` →
   `corridor.note_hero_post`）。到着一覧が読めなくても、次の城落ちで一城進める。
   - 在城一覧で主人公を確認したときも同じ記録を更新する（`deploy._observe_garrison`）。
   - 行軍中・所在不明・自軍でない城・`HERO_POST_TTL`（7200観測）超過では使わない。
   - 推定先の一覧に本人がいなければ `hero_absent` で記録を捨てる。誤った推定で
     同じ移動を繰り返さず、次の所在確認に切り替える。
2. **所在確認の訪問（`hero_locate`）**: 在城記録も推定も無いとき、国人数と
   在城・行軍・所在不明の差（`_unaccounted`）が正なら、自城の一覧を読む通常の
   移動指示を1件発行する。
   - 読み先は「前線の一つ後ろ（定位置）」→「前線」→「後方」の順。既に同じ観測で
     別の指示がその城を訪れる場合は発行しない（二重訪問をしない）。
   - `HERO_LOCATE_SPACING`（240観測）間隔・`HERO_LOCATE_BUDGET`（章あたり4回）。
     月が変われば予算は戻る。
   - 一覧を読めば通常の在城記録が更新され、次観測から主人公の移動が再開する。

前線が一城進んだときの移動先・「前線の一つ後ろ」の定義（`HERO_POST_HOPS = 3`）、
主人公を通常行軍の代役にしない規則、前線の攻撃順は変更しない。

## 検証

- 新規 `tests/test_hanjuku_hero_post_advance.py`（10件）:
  所在不明時に定位置の城を読む／既に訪問する城は読まない／直近に読んだ城は
  読み直さない／間隔と予算／月替わりで再開／行軍中は読まない・動かさない／
  推定位置から前線の追随で一城進む／推定の期限切れ／一覧に不在なら推定を捨てる／
  主人公の出発で行き先を記録する。
- 既存の第9話・corridor・州・地図・garrison 関連 164件 passed（ローカル）。
- 半熟スイートは CI が実行する。

## 本番反映後に実測すること

- 判断ログに `hero_locate_order` が出たあと、その城の在城一覧に `どうし` が
  現れ、次の城落ちで `I:c9:<城>><城>:h*` の主人公移動が発行されること。
- 主人公の移動後、到着一覧が読めていない間も `hero_post` が行き先を保持し、
  前線が一城進むごとに主人公の移動が1件出ること。
- `hero_absent` が続く局面で同じ推定移動を繰り返さないこと。
- 12話ボス撃破には未到達。目標は active のまま継続する。
