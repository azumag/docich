# 半熟英雄: おくのてだけが有効な召喚戦メニューで B を押し続ける停滞（v754、2026-11-13）

## 症状（実測 g1163 2026-11-13 04:2x〜09:2x）

第9章・城防衛の召喚戦で、画面が **5時間** 変化しませんでした。

- `hanjuku_decisions.jsonl` の直近2世代で `screen_kind=battle_menu` +
  `buttons=[b]` が 4832/5405 件、438/491 件。以後も同じ画面。
- 実際のフレームは 8 秒間隔の2枚が完全一致（アニメーションもなし）。
- 画面は きりふだ y176 / たいきゃく y192 が灰色、**おくのて y208 だけが白**。
  カーソルは灰色の きりふだ 行にあった。
- RetroArch は稼働中（CPU 15%）、入力フォーカスも `:1` の RetroArch 窓にあり、
  入力経路自体は正常でした。手動で `Down` を2回送るとカーソルは おくのて 行へ
  移動し、`A` 1回でメニューが閉じて戦闘が再開しました。

## 原因

この箱は B で閉じません（既知の g1097 と同じ挙動）。ところが光っている行が
おくのて だけなので、

- `hidden_battle_commands`（たまご/きりふだ/たいきゃく の3行すべて灰色）に当たらず、
- `disabled_item_box`（たまご+きりふだ の2行）にも当たらない。

そのため通常の戦闘メニューとして扱われ、召喚獣の照合（`okunote.summon_reading`）
も「味方行が将軍ではなく召喚獣」のため失敗し、上限到達後は
`okunote_summon_exhausted` のラッチから `None` → 汎用フォールバックの B に
落ちていました。B は効かないので、同じ画面のまま決定だけが増え続けます。

## 修正（v754 `hanjuku-chart-v754-okunote-only-box`）

- `os_layer.screen`: 実測した箱の形（灰色 きりふだ y176 / たいきゃく y192 +
  白い おくのて y208 + カーソルが灰色行）を `Screen.okunote_only_box` として
  1か所で判定する。
- `flows.battle_menus._okunote_only_box_step`: 有効な おくのて 行へ **down を
  最大4回**、行に乗ったら **A を1回**。確定が画面に反映されない場合は同一
  フレームを2回まで待ち、再確定は最大2回。下げられない/効かない場合は他の行を
  推測せず通常判定へ戻す（無記録の B 連打をしない）。
- 召喚獣の照合が失敗する経路と、照合上限を使い切った経路の両方から同じ有界手順を
  呼ぶ。従来の 3 行灰色箱（`hidden_battle_commands`）と g1075 の救済メニューは
  既存経路のまま（回帰テストで固定）。
