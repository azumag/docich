# 半熟英雄: 切り札一覧のスクロールをまとめて送る（v551、2026-11-09）

## 症状

g1163 第6話 2026-11-09 11:31 前後の15分で `card_scroll` が **68回**、`sortie_input` が
**60回**。1回の出撃あたり約8回、切り札一覧を1行ずつ下へ送っていました
（予定札は ノリウツール=ID11、クースカン=ID13、キャトルムー=ID14 など一覧の下の方）。

## 原因

`deploy` の切り札選択は、予定札が画面の4行に見えないとき **1観測につき1行**だけ
スクロールしていました。一覧はID順で在庫のある札だけを並べるため、何行先かは
`CARD_IDS` と `card_stock` から計算できます。

## 修正（v551 `hanjuku-chart-v551-card-scroll-hold`）

- `_card_scroll_frames(mem, card, inventory)`: 表示中の4行の端から予定札までの間に
  **在庫のある札が何枚あるか**を数え、その行数を返す（上限 `CARD_SCROLL_HOLD_MAX=4`）。
- スクロールは `pad(direction, frames)` でまとめて送る。1行のときは従来どおり。
- 着地点は従来どおり次の観測で読み、選択前に必ず確認する。上方向の境界判定も不変。

## 安全性

- 在庫が未読（`card_stock` に無い）札は数えない → 行数を過大に見積もらない。
- 4行揃っていない・IDが読めない・対象が不明なときは1行のまま。
- 行き過ぎた場合は従来の上方向スクロール（`_upper_card_boundary`）で戻れる。

## 確認

- `tests/test_hanjuku_departure_request.py` に1件追加: 在庫実測があるときだけ複数行、
  在庫未読・3行パネル・ID不読では1行のまま。
- 切り札・商人・出撃・チャート外 229件 passed。
- 本番反映後: `card_scroll` の回数が1出撃あたり数回に減ることを実測する。
