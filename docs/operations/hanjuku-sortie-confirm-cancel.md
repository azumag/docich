# 半熟英雄: 未確認の出撃確認を有限の拒否経路へ渡す

## コード上の再現

基本チャートのボス注文は必須携行札を緩めないため、出撃確認の持札が未読/不一致のときは、`sortie_confirm_miss` が8を超えても承認せず待ち続けていた。背景RGBが毎観測変わる合成入力では、汎用の同一画面入力なし救済も発火せず205観測すべてが入力0件となる。

また既存の有限B取消は12観測で打ち切った後、同じ出撃確認に `boss_stock_cancelled` を保持し、汎用A救済を禁止する。この安全ラッチには、実際の拒否行を選ぶ経路がなかった。

これは現行コード・合成観測の再現であり、現在進行中のゲームの原因特定や復旧を示すものではない。

## 変更

- 基本ボスの出撃確認を8観測で確認できなければ、必須札・実在庫・購入receiptを変えず、注文をpendingにして拒否ownerへ渡す。送信済み/出撃未確定のreceiptをpendingへ戻さない。
- 同一run/lease・章・stepの取消ownerだけが、最大12観測の拒否経路を持つ。JSON往復、背景変化、手や文言の読取変化で予算を戻さない。
- 既存g700ネイティブ画面の将軍見出し・携行見出し・出撃質問と両選択肢を確認し、現在の手が実選択肢にある場合だけ `いかんッ!` へ移動する。
- Aは、直前観測で自分が計画した方向入力の後、同じ将軍の拒否カーソルを次観測で読めた時だけ、一度計画する。最初から拒否行にある観測、同一観測の再実行、時刻tickの飛び、別将軍や欠落した手からは確認しない。
- 取消要求は取消成立ではない。後続の将軍一覧/札選択には予算内のBで退出を要求し、自由マップまたは城メニューを観測して初めてownerを解除する。別の戦闘・月次・支払い確認は横取りしない。
- 上限後に実復帰を読めなければ安全側のdeferを保つ。危険な出撃承認、汎用A、無限Bで見かけの進行を作らない。
