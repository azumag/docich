# 読めない画面が固まったらAを1回だけ送る（v428、2026-11-05）

## 症状（実測）

`situation_held` が30分で **35件**。中身はすべて
「状況判定保留: 文字・カーソル・戦闘表示を読めない画面」で、
**入力を送らずに待つ**だけの観測が繰り返されていました。

- 画面が固まったまま（同じフレーム）でも待ち続けるため、観測を消費するだけでした。
- ゲームの画面の多くは1回のボタンで進むので、固まったままなら1回送るのが妥当です。

## 変更

- `orchestrator.unknown_hold_advance(screen, mem, actions, digest)` を追加。
  読めない画面のフレームダイジェストが `UNKNOWN_HOLD_ADVANCE`（6）回連続で同じなら、
  **A を1回だけ**送って進める（`unknown_hold_advance` を記録）。
- 画面が反応すればダイジェストが変わるので、上限には達しない。
- 読めない画面でなくなったら監視状態を捨てる。

## 検証

- `tests/test_hanjuku_unknown_hold.py`（新規3件）: 変化する画面では押さない／
  固まった画面は1回押してから再び待つ／既存の入力は上限まで維持。
- 関連（`chart_bot` / 層）335 passed。
