# 半熟英雄: 画面・実入力の反復ループによる停滞終了

## 目的

2026-10-14のオーナー依頼: 単一画面の停滞だけでなく、複数の画面や操作を巡回するループも検知し、既存の停滞時と同じくセーブして一旦終了し、再起動に備える。

月初メニューなどの個別の根本原因修正を置き換えず、再発時の安全網とする。戦略・兵士補充・卵回復の規則には触れない。

## 判定

- フルRGB画像のSHA-256、認識phase、直前の観測以降に実際に送信された入力の順序を組にする。予定した入力だけでは証拠にしない。ボタン保持時間だけの違いは進行とはみなさない。
- 連続する同じ組は1段階に圧縮する。画面に滞在する観測回数が多少違っても周期を追跡する。
- 2〜24段階の同じ並びが少なくとも4周し、その連続した周期区間が既存の`STALL_SECONDS`（300秒）以上続いた場合、次の周回完了時に停滞を確定する。
- 同じボタンだけ、同じphaseだけ、入力のないアニメーション、短い反復だけでは周期停滞にしない。従来の静止画面・入力途絶の判定は別に維持する。
- 15秒を超える観測欠落、一時停止、時計の巻戻り、確認された戦闘の開始・終了では履歴をリセットする。新しい画面や入力順序が周期に一致しなければ候補を破棄する。
- 履歴は最大96段階。runtime/generation/leaseは既存`hanjuku_run.load()`の照合に従い、別世代へ引き継がない。新しい実行では新たに判定する。

これは完全一致する画面・入力列の検出であり、画像が毎回異なるアニメーションや24段階を超えるループ、見た目が似ているだけの意味的なループまで検出できるとは扱わない。フル画像を使うため、画面上のHP・資金・台詞等の変化を無視して同一状態へ丸めない。ROM実画面での検出率と誤検知率は別途実測が必要。

## 既存の保存・終了契約

終了理由は互換性のため`screen_stalled`を使用し、`terminal_evidence = repeated_screen_input_cycle`で単一画面の停滞と区別する。新しい強制終了経路や再起動ループは作らない。

`hanjuku_run.terminal()`は保存前・cleanup前に周期証拠を再検証する。その後は既存のRetroArch停滞終了経路により、対象世代のチェックポイントを保存・検証してから終了する。保存失敗・欠損・変更時に正常終了扱いや未保存の強制停止へ進めない。配信エンコーダ、共通音声、他ゲームの制御は変更しない。

この変更は「セーブして停止し、既存の再開処理へ渡せる状態にする」まで。停止直後に同じ状態を無限に自動再起動する機構は追加しない。

## 観測項目と互換性

`hanjuku_run.json`に次を追加する。

- `repetition`: 上限付き周期履歴と候補。周期・周回数・開始時刻・最後の周回完了時刻を含む。
- `repetition_input`: 実入力をまとめる一時的なハッシュ。次の観測で消費して空に戻す。
- `repetition_evidence`: 確定した周期長、周回数、継続秒数、周期のハッシュ。未確定時はnull。
- `frame_unchanged_since` / `frame_unchanged_seconds`: 従来の2画像以内の点滅を含む、文字どおりの画面停滞時計。

既存の`unchanged_since` / `unchanged_seconds`は通常時には従来の画面停滞時計を維持する。周期停滞で終了するフレームだけ、検証済みの反復区間の開始時刻・実際の継続秒数を記録する。固定値300を捏造するものではない。静止時間と周期時間を区別する表示・調査では`terminal_evidence`と`frame_unchanged_seconds`を見る。

終端の`hanjuku_events.jsonl`にも周期の要約と実際の画面停滞時間を記録し、既存同様、終了状態を書き込む前にログをfsyncして終了画像を保存する。

## テスト

```sh
python3 -m pytest -q tests/test_hanjuku_repetition.py tests/test_hanjuku_repetition_run.py tests/test_hanjuku_repetition_checkpoint.py tests/test_hanjuku_stall_checkpoint.py tests/test_hanjuku_script.py
```

新規テストは、周期検知・継続時間・4周条件・滞在回数の違い・進展・入力記録なし・観測欠落・pause・時計巻戻り・履歴上限・不正証拠・別lease・旧静止判定・保存成功/失敗・保存の冪等性・cleanup後のセーブ保持を対象にする。既存CIの`tests/`全探索で実行する。

実装時のローカル検証: 周期検知の単体42件は成功。観測・JSON保存・終端再検証を含む12件は周辺依存を代替したローカルハーネスで成功。合計54件。このハーネスの成功を実アダプターや実ROMでの成功とは扱わない。実アダプターを使う新規3件、既存停滞関連、全体CIは正規リポジトリ環境で別途確認する。
