# 卵回復を見送った月の兵士補充

2026-10-15のオーナー指示は、従来の「回復費が足りない月は兵士補充も0」の方針を、不足する兵士について置き換える。回復できる卵を先に回復する順序は維持する。

## 判断

同一実行・章・月で実兵数を確認でき、50人未満で、当月の卵回復が支払い前に見送りとなった場合、賃金不足への既存予備・家修理費・未購入の必要品を除いた実残金で50人まで補充する。全額が足りなくても買える人数を補充する。兵士不足を止めるための卵予算と未実行の募集費は補充へ回す。卵の残数・回復対象・履歴は書き換えず、回復済みとは扱わない。50人以上なら、この例外で追加購入しない。

完全な現在名簿に回復対象がいない場合は既存の名簿照合を使い、回復見送りの例外とは区別する。名簿が不完全でも、実兵数と実資金が確認でき、支払いが未確定でない場合の補充は可能だが、卵所有者が消えた・回復したとは推測しない。

## 支払いと有限性

- 未読・別実行・前月の兵数からは補充の例外を開始しない。
- 進行中の儀式、支払待ち・支払済み・未確認の兵士購入、未確認の募集、失敗済みの人数確認・補充要求を再実行しない。
- 回復画面からの中止は、確定前・同月・静かな月初メニュー復帰・残金不変を照合できた場合だけ見送りとする。確定送信後は残金が同じでも未払いと決めつけない。
- `soldier_egg_deferral` はJSON保存され、同一実行・章・月に一度だけ計画を作り直す。毎観測で許可を再確認し、終了済みの計画や読み取り・入力の上限は復活させない。
- 数量入力後の支払実測と兵数加算は既存の `soldier_refill_receipt` を使い、計画やA入力だけで補充完了としない。

診断イベントは `soldier_refill_after_egg_skip`、回復中止の照合は `egg_recover.observed_metric.unpaid_decline_verified`。`egg_recover` の `payment_verified` とは別の意味である。

## 反映

PRのテスト・レビュー後にmainへ統合し、既存のVM operationsから正規配布する。戦略・月次手順の変更は観測ごとのBotサブプロセスで読み込む。配信全体やゲームをこの変更のために再起動しない。CI成功、VMへの配布、実際の兵士購入・人数増加はそれぞれ別に確認する。
