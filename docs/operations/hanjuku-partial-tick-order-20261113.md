# 半熟英雄: 古いページ下限が新しい完全読みを上書きしないようにする（v766、2026-11-13）

## 症状（実測 g1163 2026-11-13 15:0x）

`オオキク` の実際の在城者は **2人**（キール / ロックフォール）でしたが、
古い一覧ページの `garrison_partial` には4人
（ローズマリー / リーキ / プラリネ / マーマレード）が残っていました。

`corridor._front_names()` は `garrison` と `garrison_partial` の**長い方**を
返していたため、前線は4人と誤認されました。その結果:

- 2人待ち（`_mass = _keep + 2`）の条件を満たしたと判断し、攻撃を開始。
- 実際には2人しかいない前線から1人を出撃させ、1人だけ残して
  `オオキク` が敵の反撃で落ちる一因になりました。

## 原因

`garrison`（完全読み）と `garrison_partial`（ページ下限）に時刻がなく、
「長い方」を採るしかありませんでした。v700 の「ページが完全読みに無い
同僚を証明する」ケースは残す必要がありますが、**ページが古い**場合は
完全読みを優先すべきです。

## 修正（v766 `hanjuku-chart-v766-partial-tick-order`）

- `_observe_garrison` が完全読みで `garrison_tick[城]`、ページ読みで
  `garrison_partial_tick[城]` を記録。
- `_front_names` は両方に tick があるとき**新しい方**を返す。
  - 完全読みが新しければ、短くてもそちら（今回のケース）。
  - ページが新しければ従来どおりページ（v700 のケース）。
  - tick が無い旧 state は従来の「長い方」を維持。
- 完全読みが空（`[]`）で新しければ、空を返す（古いページの幽霊を消す）。

## 検証

- 新規テスト3件（`tests/test_hanjuku_partial_page_residents.py`）
  - 新しい完全読みが古いページに勝つ
  - 新しいページが古い完全読みに勝つ
  - tick 無しは従来の長い方
- 第9話 corridor / 派遣 / 城ルート / 前線 / capture guard / probe 関連
  **202件 passed**。
- 修正前の `corridor.py` では「新しい完全読みが勝つ」テストが失敗することを確認。

## 本番反映後に実測すること

- 完全読みの後、`_front_names` が実際の人数（例: 2人）を返すこと。
- 前線が4人に見える状態で攻撃を始め、1人だけ残して落とす、という
  取り違えが再発しないこと。
- `garrison_tick` / `garrison_partial_tick` が更新されること。

## 残件

- ページと完全読みの優劣は tick で決めるが、同時 tick の場合は完全読みを
  優先する（現実装）。ゲーム内の同時更新はほぼ無い。
- 第9話の進行と12話ボス撃破は引き続き実測で確認する。
