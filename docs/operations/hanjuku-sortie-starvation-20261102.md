# 半熟英雄の出撃停止（g1097、2026-11-02）

## 症状

第5話で、新しい出撃が tick 33014 から tick 47460 まで1件も出なかった（ログから約4.6時間と推定）。この間に城4つが敵の手に渡り、完全な名簿の人数も減り続けた。本拠地には待機中の将軍がいた。

## 実測

04:30〜06:08 の判断ログの内訳は次のとおり。

| 画面 | 時間の割合 |
| --- | --- |
| テキスト（将軍の全件スキャンなど） | 57.6% |
| マップ | 12.4% |

マップ画面の観測491回のうち400回は入力なしだった。`world_map_tick` は tick 32126 のままで、`map_step` の出撃判断まで届いていなかった。

## 原因

`hanjuku_house.step` は `map_step` より先に走るため、修理セッションが残っている間は出撃の判断が動かない。3つの欠陥が重なっていた。

1. **屋根合わせの回数がリセットされない。** `align_steps['HOUSE:source']` は同じ章の中で積み上がり、838に達していた。上限10を超えると `_align_on_roof` が `None` を返し、`aligned or []` で25観測の空待ちのあと延期になる。同じフレームで履歴を空にすると補正入力を返す。
2. **台帳が離脱した将軍の修理を残す。** ゼウスとセミヨンは完全な名簿にないのに、卵の破損記録だけで `repair` 目標が残った。`repair_due` が真のままになり、月内の間隔制限を素通りした。
3. **「空き時間」の判定がなかった。** 台帳の再開は、`active` などの有無しか見ていなかった。出撃できる指示があるかどうかは見ていない。

## 修正（v353）

- 城へジャンプするたびに `HOUSE:source`、`HOUSE:income`、`HOUSE:return` の回数を消す。
- 完全な名簿にない将軍は `goal_departed` に記録し、名簿に戻るまで修理目標にしない。スキャン中は `complete` が偽になるので、結果を覚えて再登録を防ぐ。
- `map_step` が指示なしと判定した直後の2観測だけ、台帳による予算超過を許す。

通常の月次スキャン（月2回まで）の順序は変えていない。

## 確認の仕方

`bot_version` が v353 になったあと、次を見る。

- `chart_adjust_request` と `order_start` が再開し、`sorties` に新しい行が増える。
- `align_steps['HOUSE:source']` が10を超えて増え続けない。
- `goal_resolved` でゼウスとセミヨンの修理目標が外れ、`goal_departed` に入る。
