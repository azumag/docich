### 1.1 S0 の実測(2026-11-22、`report_s0_probe.md`)

### 1.2 既存のバグ(S0 から)
- 出撃パネルの読みは、すでに携行を引いた後の値になっている。そのため #4429 の `held_estimate = stock + 買い − 使用` は、戦闘で使った分を二重に引く。M1 でも M2 でも所持を少なく見積もり、頼みすぎる。S2 で置き換える。
- S1(矢印の判定)で止まるのは、v1333・v1334 型(窓の読みで0枚に書き換えられた札)。v896 型(一度も窓に写っておらず、キーが無いので0枚として扱われる札)は、S2(未知の札は余剰金で買わない)まで残る。

## 2. 何が悪いか(原因)

探り買いは症状で、原因は**所持数を知らないまま買っていること**。
1. 誤0化(F4): 「4行未満=全所持」の推定が、末尾窓や携行直後の窓で外れる。
2. 台帳の消去(F6): パネルを読むたびに購入・使用の記録を捨てる。窓に写っていない札は、24種の上限で捨てられ、0や未知に戻る。
3. 未知を0として扱う: `held_estimate` は未知の札を0として数え、`_rich_room` は 99−0=99 を頼む。
4. 拒否を測定に使う: 拒否のたびに下限を学び半分で聞き直す(v1329 で二分探索化)。

## 3. 設計: 切り札の台帳

### 3.1 台帳 `card_ledger`(新規。WORLD 領域、ラン単位)
種類ごとに `{count:int|None, basis:'full'|'window'|'derived', at:<観測step>}`。
- `count=None` は未知。未知は0として扱わない。
- 増減は bot が起こした出来事だけで動かす:
  - 購入: 見積の照合(既存)と所持金の減少を確かめたら `+q`。拒否されたら加えない(既存の `paid_nothing` 判定を流用)。
  - 携行: 出撃のきりふだ選択で確定した枚数だけ `−n`(S0 で実測)。
  - 使用: 台帳は変えない(携行した時点でフィールドから引かれているため。S0/S0b)。
  - 帰還: 携行して使わなかった札が帰還・撤退で戻るかは未確認。戻ればパネルや一覧の読みとの食い違い(`ledger_drift`)で見つかり、読みで直す。
- 上限の計算はフィールド在庫だけで行う: 頼む枚数 = `99 − count`(S0b で確定。携行分は引かない)。
- 読み:
  - **窓の読み**(出撃パネルの4行など): 写っている行だけ、その値で上書きする(`basis='window'`)。写っていない札は変えない。
  - 「無い」と言えるのは、ID順の窓で上下両隣が写っていて、その間の ID が無いとき(既存の ID ギャップ証明は残す)。
  - 「4行未満=全所持」は、在庫が3種以下の序盤でボス札の欠品を見つける規則(#2374 / `_card_proven_absent`、g825)なので、やめずに**条件を狭める**。たとえば「このパネル操作で下へ送っておらず、先頭から写っているときだけ全所持」。正しい条件は U4 の実測で決める。
  - **全量の読み**(一覧を末尾まで送った読み): 全種を上書きし、写っていない札は0(`basis='full'`)。
  - 読みが台帳と食い違ったら、読みを正にして `ledger_drift` を記録する(U2 の検出)。
- 台帳は消さない。今の「パネルを読んだら購入・使用・下限を消す」はやめる(読みで上書きするので、消す必要がない)。
- 統合する既存の台帳: `card_stock`、`card_bought_since_read`、`card_used_since_read`、`card_held_floor`(廃止)、`boss_cards.UNSEEN`(`card_bought_unseen`)。
- **未知に戻す条件**: 再開(resume)、巻き戻し(start.state の rollback / recover)、runtime の世代交代、ゲームオーバー。ゲームと mem が食い違いうる場面では、ずれた台帳を正としない。
- lifetime: 在庫が章をまたいで持ち越されるなら 'run'(U5 で決める)。今の `card_held_floor` などは 'chapter'。
- `CARD_STOCK_LIMIT=24` は今回変えない(11-06 にオーナーが据え置いた項目で、今回の0への書き換えの原因ではない)。→ 2026-11-26 にオーナー指示で全32種へ変更（末尾の追補）。

### 3.2 購入の計画(差分だけ)
- 頼む枚数 = `min(目標 − count, 99 − count, 予算 // 単価)`(count はフィールド在庫。携行分は含めない。S0b)。
- `count` が未知のとき:
  - **余剰金の買い足し**(bargain / rich / 行商人): 頼まない。
  - **必需品**(チャートの購入、boss_cards のボス札の買い戻し): 今までどおり必要な枚数だけ頼む。断られても1回で済む。ラン開始や再開の直後は台帳がすべて未知なので、ここで必需品を止めると退行になる(g825 ではボス札欠品で出撃が41分止まった)。
- 商人は今までどおり毎月開く(品揃えは月ごとに変わり、rich のランダム札も一覧を読んで決めるため。閉じるのは1回約3秒で、時間の問題はここにない)。
- 一覧で選ぶ順は、画面の並び順にする(カーソルの往復を減らす)。
- 目標(オーナー判断、§5):
  - 目標は種類ごとに99枚。減った分だけ毎回買う(閾値なし。オーナー決定 §5)。

### 3.3 拒否の扱い(探り買いの廃止)
- 拒否は「台帳がずれた」という印。その札の `count` を未知にし、この訪問ではその札をやめる。半分にして聞き直さない。
- 同じ訪問のほかの札は続ける(F3: 札ごとの上限なので、他の札は買える)。
- 次の全量読みで台帳を直す。
- `card_held_floor` の学習と二分探索(v1329)は削除する。拒否の文言に気づいて閉じる処理(`_holding_limit_step` の A)は残す。

### 3.4 全量の読み(未知の札を減らす)
- 対象: 未知の札があり、その札が購入の対象になる月。
- 方法は U3 / U4 の実測で決める。候補は2つ:
  - (a) 月の行動の前に、フィールドの X→「きりふだ」を末尾まで送る。
  - (b) 出撃のきりふだ選択で、選ぶついでに末尾まで送る。
- 頻度は、ずれ(`ledger_drift`)か拒否が出たときと、ランの初回だけにする。
- 毎月は読まない。台帳の増減は bot の行動だけで決まるので、ずれない限り読み直さない。

### 3.5 残る時間の削減(上の効果を確かめてから)
- 数量入力の一括化: 今は1観測1キーで最大約11観測。キー列は決定的なので、1観測にまとめて押し、次の観測で値を照合できる。差分管理の後でも品目数が多いときに効く。
- shop_quantity_prompt / shop_quantity の無主保留: #4650 の担当と連携して、同じ仕組みに入れてもらう(重ねて直さない)。

## 追補（2026-11-26、v1519）: 台帳の上限を全32種へ

オーナー指示（2026-11-26）で `CARD_STOCK_LIMIT` を 24 から全カタログ種（32）へ広げた。

- 背景: 2026-11-25 に商人の購入対象を16種へ広げた。24種上限は、出撃パネルの窓読みが
  新しい種を足したときに挿入順の先頭を落とす（`while len(stock) > CARD_STOCK_LIMIT:
  stock.pop(next(iter(stock)))`）。落ちた項目が購入対象の 0 なら、S2 は未知の札を
  余剰購入しないため以後買えなくなる。この追い出しはコードと単体テスト
  （`test_a_zero_buy_target_survives_a_binding_stock_limit`）で確認している。
- 実測の補足: g1342 14-2 の `known: 24 -> 21` は2回観測したが、どちらも未確認送信の
  出撃取り消し（01:18:26 `order_launched_unconfirmed` / 01:39:27 `sortie_unverified_rearmed`
  → `forget_picked`）で携行札を未知に戻す既存規則によるもので、24種上限の追い出しは
  この実測では観測されていない（訂正）。
- 変更: `CARD_STOCK_LIMIT = len(reference.ALL_CARD_IDS)`（32）。全所持読み直しは全種を
  上書きし、写っていない札は 0 として残る。調整チャート要求に載る名前が最大32件になるが、
  8件増えるだけでサイズ影響は軽微。
- 残すもの: トリムの順位（購入対象の0を購入優先度順に残す）は、将来カタログが増えて上限が
  再び絞られた場合の保険として残す。S2 の「未知は余剰購入しない」規則は変えない。
