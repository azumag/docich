# あけまつ：能力交換は一度だけ、その後「おもてなし」（2026-10-16）

オーナー指示：あけまつが「ごあいさつ」を延々と選んでしまうため、**最初に1回だけ「ごあいさつ」で能力値を相手と入れ替え、その後は「おもてなし」で別のエッグモンスターを召喚**する。

攻略資料：
- [RRPG その他のエッグ](https://rrpg.jp/hanjuku_hero_2/special.html)：「ごあいさつ」は能力値の入れ替え、「おもてなし」はエッグモンスター召喚。
- [SFC基本情報](https://w.atwiki.jp/gameguidesite/pages/28.html)：かどまつエッグのあけまつは「おもてなし」で他の召喚獣に交代する。

## 決定ルール

味方のあけまつ、かつ技が正確に「ごあいさつ」「おもてなし」の2技と確定できるメニューにだけ適用する。

1. 現在の戦闘/将軍/相手モンスターを識別でき、まだ「ごあいさつ」の選択を送信していない場合は技1を選ぶ。
2. **実カーソルが技1上にある状態でAを返した時だけ**、battle.akematsu_exchange.greeting_submitted を真にする。メニュー表示・カーソルの予測・移動要求だけでは真にしない。
3. 次の技メニュー観測から、HPの変化の有無にかかわらず技2「おもてなし」を選ぶ。generic experienceで再び技1へ戻さない。
4. メニュー選択のキャッシュが以前の版から残っていても、新戦術の版ID、あるいは予定されている技が前回と異なれば再決定する。
5. 別戦闘/相手/将軍に変わる場合は送り済み状態を失効し、再び1回の「ごあいさつ」から始める。戦闘の識別に失敗した場合は、再交換ループを避けて「おもてなし」を選ぶ。
6. 敵側のあけまつは操作しない。カーソル移動だけで選択完了を記録しない。ゲーム・配信・音声・他召喚獣の制御は変更しない。

この状態は**確認済みのボタン送信指示**を記録しており、実際の交換成功や能力値の変化を読んだ証拠ではない。交換が行われなかった場合も誤って成功と記録しない。HPや戦況だけで交換が成功したと推測しない。

検証：
- tests/test_hanjuku_akematsu.py：技1A→同HPで技2へ移動→技2A、古い技1キャッシュ、相手変更、敵所有、未知カーソル、保存復元。
- tests/test_hanjuku_chart_bot.py：合成したエッグモンスター技メニューを本物の画面判定器で読み取り、技1→技2の操作列を検証。

実戦ログで確認すべき項目は monster_menu_choice の observed_metric.akematsu_exchange（greeting_submitted と rule）、実カーソル、送信済み入力、交代後の召喚獣名。単体・CI成功は実戦の交代成功の証明ではない。
