コーナーローテーション


配信の「コーナー」（レトロゲーム・NetHack・PAPER・メリケン・天気）は、ローテーションが自動で1つずつ起動します。一度実行したコーナーは cooldown（既定24時間）が明けるまで自動では選ばれません。この画面は10秒ごとに自動更新されます。

コーナー一覧


各コーナーが次に自動で選ばれるかどうかと、選ばれない場合の理由です。行を押すと、下の手動操作の対象に選ばれます。


コーナー種類自動選択最終実行cooldown 明け稼働/手動の状態




手動操作


使い方:

① 手動開始: コーナーと分数を選んで1回だけ実行します。天気は現在のコーナー終了後に開始する予約で、表示時間は設定済みの分数です。予約中は開始後に停止できます。実行中はローテーションの自動起動が待機します。

② 手動停止: 手動開始・ローテーション自動起動のどちらで動いているコーナーでも、停止可能な状態なら途中で終わらせ、元のゲームへ戻します。

③ ローテーション復旧: 状態が「要復旧」で止まったときだけ押せます。先に該当コーナーの停止/復旧を済ませてください。

stop は tmp/state/direct_stream.paused マーカー作成後、lib/direct_stream.py stop を実行し FFmpeg stdin へ q を送って RTMP 正常終了 (FCUnpublish / deleteStream) させます。Twitch が「意図的な終了」として即座に OFF LINE にするための正規手順 (wiki: Stream-Ending)。強制切断だと回線断扱いになり LIVE が最大90秒残ります。start はマーカー削除後、supervisor の自動再起動 (約3秒周期) を最大20秒待ちます。




チャット送信の停止 / 再開
tmp/state/chat_worker.paused で制御。停止中は IRC 受信・コメント生成・投稿キュー消費が止まり、新規 enqueue も積まれません (worker が自己 park / marker 削除で自動復帰)。












予想・改善ワーカーの停止 / 開始
prediction_worker / improve_daemon を supervisor の pause gate (tmp/state/<name>.paused) で制御。stop はマーカー作成後に SIGTERM、start はマーカー削除後の supervisor 自動再起動 (約3秒周期 + backoff) を最大30秒待ちます。




improve_daemon を停止すると、稼働中の改善ジョブと AI 子プロセスもツリーごと停止します。予想ワーカー停止中は Twitch 予想の自動作成・解決が止まります。

モデルチェーン
カンマ区切りで優先度順。先頭が最優先で失敗時に次へフォールバック（lib/ai_generate.sh）。AI_COMMON_AGENTS が原典で、他は空ならそれを継承します。各行の ⏸ で一時停止でき、停止中のモデルは順序と位置を保ったまま保存時にチェーンから除外されます（▶ で同じ位置へ復帰）。停止位置は <CHAIN>_PAUSED (index:agent) として .env に保存。変更は .env へ原子書き込み → 10秒以内に hot-reload。






保存後に radio/chat の reload を自動試行します（PIDファイル経由 USR1）。











モデル別バックオフ設定
AI_BACKOFF_SEC_ITEMS は "model:sec" を空白区切り。例: deepseek-v4-flash-free:86400 local:1800。レート制限(429)はモデル別の長バックオフ、AI_BACKOFF_FAILURE_SEC は一過性のプロバイダ/CLI失敗に使う短いバックオフ。
